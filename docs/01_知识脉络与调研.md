# 从强化学习到大模型与智能体的知识脉络

## 1. 报告的中心问题

强化学习研究的是：一个决策者通过行动影响后续经历，又只能获得不完整、可能延迟的反馈时，怎样改进行为。报告最有价值的连接点，是把游戏中的“行动—反馈—改进”映射到大模型的“生成—验证—更新”，再扩展到智能体的“观察—调用工具—再次观察”。

教学上可以围绕三个问题推进：什么结果值得鼓励；一次成功应该归因给哪些动作；一次更新多大才合理。DQN、策略梯度、Actor–Critic 和 PPO 分别从不同角度回答这些问题。下面的示例和推导是教学性重述，算法出处见脚注；文献事实与实践建议分别标明。

### 1.1 关系图

```text
强化学习：最大化与环境交互得到的期望回报
│
├─ 价值路线：Bellman → Q-learning → DQN
│                          │ 借助价值估计评价行动
└─ 策略路线：REINFORCE → baseline → Actor–Critic → GAE → PPO
                                                        │
                   大模型：策略变为自回归语言模型          │
                   ├─ 人类偏好 → 奖励模型 → PPO-RLHF ──────┘
                   ├─ 偏好对 → DPO（另一种优化路线）
                   └─ 可验证结果 → 策略梯度／GRPO 等
                                      │
                         代码执行、工具交互、多轮环境
```

这张图表示知识依赖与方法联系，不表示严格年代或取代关系。GRPO 可以使用学习得到的奖励；PPO 也可以使用程序给出的奖励。“奖励从哪里来”和“怎么优化策略”是两个独立维度。

## 2. 基本概念：先用一个可贯穿全场的例子

想象一个虚拟房间：智能体要先找到钥匙，再开门，最后抵达目标。移动本身没有正奖励，任务完成时得到 1 分。直接冲向门看起来离目标更近，却可能永远打不开门。这个例子同时包含延迟奖励、探索、信用分配和多步规划。

### 2.1 最小符号表

| 符号 | 含义 | 房间任务 | 大模型任务 |
|---|---|---|---|
| \(s_t\) | 状态；足以决定转移分布的信息 | 位置、朝向、门和钥匙的状态 | 理想化的完整交互历史或任务状态 |
| \(o_t\) | 实际可见的观测 | 局部画面 | 当前上下文、工具输出 |
| \(a_t\) | 行动 | 移动、拾取、开门 | token 或一个完整工具调用 |
| \(P\) | 转移规律 | 物理／游戏引擎 | 拼接文本；或外部工具／环境执行 |
| \(r_t\) | 本文约定：执行 \(a_t\) 后收到的奖励 | 到达目标得分 | 答案验证、测试结果、偏好分数 |
| \(\pi_\theta\) | 策略 | 各动作的概率 | 下一 token 的概率分布 |
| \(G_t\) | 从时刻 \(t\) 开始的累计回报 | 后续成功与代价 | 后续任务收益与成本 |

MDP 通常写成 \((\mathcal S,\mathcal A,P,r,\gamma,\rho_0)\)。有限回合目标为

\[
G_t=\sum_{k=t}^{T-1}\gamma^{k-t}r_k,\qquad
J(\theta)=\mathbb E_{\tau\sim\pi_\theta}[G_0].
\]

\(\gamma\) 是未来收益的折扣；有限长度、只在回答末尾计分的 LLM 任务常采用不折扣的形式。它不是“模型有多聪明”的参数。这里统一使用执行动作后的 \(r_t\)；有些教材记成 \(R_{t+1}\)。[^1]

### 2.2 必须讲清的四个区别

**奖励与监督标签。** 标签通常告诉模型应该输出什么；奖励只评价这次尝试。一个任务可能有很多正确策略或正确程序，奖励可以允许它们共同存在。但 RL 仍需要任务、环境或验证规则，并不意味着没有数据。

**训练和推理。** 训练时从轨迹计算梯度并更新权重；推理时多采样、搜索、反思、调用工具，可以完全不更新权重。工具使用次数更多不能单独证明做过 RL。

**状态与观测。** 门后面有什么可能不可见；代码仓库也不可能永远完整地放在上下文里。理论上可以用完整历史构造状态，现实里的上下文截断、摘要和隐藏信息仍带来部分可观测问题。

**on-policy／off-policy 与 online／offline。** 前者关心数据由什么策略产生、要优化什么策略；后者通常关心训练中能否继续获取交互数据。术语在不同社区略有差异，讲时给出具体含义：PPO 主要使用近期行为策略轨迹；标准 DPO 经常使用固定偏好数据；DQN 从回放池学习。

## 3. DQN：先学会评价行动

### 3.1 从价值到 Bellman 关系

\[
V^\pi(s)=\mathbb E_\pi[G_t\mid s_t=s],\qquad
Q^\pi(s,a)=\mathbb E_\pi[G_t\mid s_t=s,a_t=a].
\]

\(V\) 评价“现在这个处境”；\(Q\) 评价“在这里做这个动作，然后继续行动”。最优动作价值满足

\[
Q^*(s,a)=\mathbb E[r_t+\gamma\max_{a'}Q^*(s_{t+1},a')\mid s,a].
\]

关键思想是自举：用已有的下一步价值估计，构成这一步的学习目标。它提供了反馈向前传播的机制，也带来“估计误差影响另一个估计”的风险。表格 Q-learning 的收敛条件不能直接搬到任意神经网络上。[^2]

### 3.2 DQN 的训练闭环

1. 以 \(\epsilon\)-greedy 等行为策略探索，收集 \((s,a,r,s',d)\)。
2. 从经验回放池抽样，降低连续样本相关性，并复用交互数据。
3. 用延迟更新的目标网络形成目标：
   \[
   y=r+\gamma(1-d)\max_{a'}Q_{\theta^-}(s',a').
   \]
4. 更新在线网络，使 \(Q_\theta(s,a)\) 接近 \(y\)，目标端停止梯度。
5. 周期性同步目标网络。

这里 \(d\) 表示真正的终止；外部时间限制导致的截断是否应 bootstrap，需要看任务定义，不能只看一个合并的 `done`。平方误差适合解释；实现也可能采用 Huber 类损失、梯度裁剪等。

DQN 的代表性突破是将高维视觉输入、神经网络价值估计和游戏交互结合。2015 年论文在 49 款 Atari 游戏上评估，不应说成“每个游戏都超过人类”。回放与目标网络是报告应留下的两个技术点。[^3]

### 3.3 为什么不直接用 DQN 解释所有 LLM 训练

语言模型本来就在输出动作概率，而自然语言的序列空间巨大。虽然词表是有限离散集合，原则上可以研究 token 级 Q 方法，但为丰富上下文建立可靠价值、处理长延迟回报并对动作做改进并不轻松。更自然的过渡是：既然已有一个能生成语言的概率模型，能否直接提高好输出的概率？这是策略梯度的入口，而非 DQN 的逻辑失败。

## 4. REINFORCE：直接改进行动概率

### 4.1 一个二选一的教学例子

假设策略选择 A 或 B，选 A 的概率为 \(p=\sigma(z)\)。本次选中了 A，取得回报 \(R\)。因为 \(\partial\log p/\partial z=1-p\)，当 \(R>0\) 时，沿 \(R\nabla\log p\) 更新会提高 A 的概率。换成复杂网络和整条轨迹，思想相同：按结果调整已采样行动的概率。[^4]

若环境动力学与策略参数无关，利用对数导数恒等式，有

\[
\nabla_\theta J
=\mathbb E_{\tau}\left[G_0\sum_t\nabla_\theta\log\pi_\theta(a_t\mid s_t)\right].
\]

为了简化讲述，后续策略梯度采用有限回合 \(\gamma=1\)。由因果性，可以把整回合回报替换为该动作之后的 reward-to-go：

\[
\nabla J=\mathbb E\left[\sum_t G_t\nabla\log\pi_\theta(a_t\mid s_t)\right].
\]

若回到前述折扣初始状态目标，严谨的轨迹表达式需保留外侧 \(\gamma^t\)，或在折扣状态访问分布的定义中吸收相应权重。讲稿不在这两种约定之间切换。

### 4.2 为什么需要 baseline

在不同难度的状态拿到同样回报，意义可能不同。可用只依赖状态、不依赖当前采样动作的 \(b(s_t)\) 做比较：

\[
\hat g=\sum_t(G_t-b(s_t))\nabla\log\pi_\theta(a_t\mid s_t).
\]

其核心恒等式是

\[
\mathbb E_{a\sim\pi}[b(s)\nabla\log\pi(a\mid s)]
=b(s)\nabla\sum_a\pi(a\mid s)=0.
\]

因此，在适当条件和正确停止梯度的实现下，可以减小方差而不改变期望梯度。不要把任意由同一组样本算出的 baseline 都自动称作严格无偏；组均值包含自身样本时，要单独分析缩放和相关性。[^1]

### 4.3 优势函数

\[
A^\pi(s,a)=Q^\pi(s,a)-V^\pi(s).
\]

优势回答的是：相对在这个状态下的平均表现，这个行动好多少。它不是奖励的别名。一次行动的即时奖励可能为零，但它取得钥匙、提高了未来成功概率，因而仍可有正优势。

## 5. Actor–Critic 与 GAE

Actor 输出策略，Critic 估计价值。Critic 不一定是独立的大模型，也可以是共享骨干上的价值头；是否共享取决于实现。典型 TD 误差为

\[
\delta_t=r_t+\gamma(1-d_t)V_\phi(s_{t+1})-V_\phi(s_t).
\]

可以用它或多步版本估计优势，并用价值目标训练 Critic。Actor–Critic 是一类结构，A3C 是有代表性的具体方法；不能把 A3C 当作 Actor–Critic 思想的最初起点。[^5]

GAE 把多个时间尺度的 TD 误差组合起来：

\[
\hat A_t^{\mathrm{GAE}}=\sum_{l\ge0}(\gamma\lambda)^l\delta_{t+l},
\]

实际必须在回合边界停止递推。较小 \(\lambda\) 更依赖短期 bootstrap，较大 \(\lambda\) 更接近长程回报；这是方差、偏差和价值误差之间的权衡，不能绝对化为“越大越准确”。[^6]

过渡到 PPO 的问题：即使优势估计不错，如果一下把策略改得太多，旧轨迹还能可靠地指导新策略吗？

## 6. PPO：限制更新激励，而非保证策略不动

### 6.1 行为策略与概率比

\[
\rho_t(\theta)=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{\rm old}(a_t\mid s_t)}.
\]

\(\pi_{\rm old}\) 是生成这批数据时的策略快照；更新期间分母固定。PPO-Clip 的核心目标是

\[
L^{\rm clip}(\theta)=\mathbb E_t\left[
\min\left(\rho_t\hat A_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t\right)
\right].
\]

当优势为正，提高该动作概率是好方向，但超过一定幅度之后不再获得更多局部奖励；当优势为负，过度降低概率也会被限制。举例取 \(\epsilon=0.2,A=2,\rho=1.5\)，两项是 3 与 2.4，取 2.4。若 \(A=-2,\rho=0.5\)，两项是 -1 与 -1.6，取 -1.6。这个负优势例子值得现场讲，否则听众容易误以为只限制概率增大。[^8]

### 6.2 三个容易误解的地方

- clip 作用于优化目标，不是把模型全部概率硬截断到区间；共享参数更新仍可能使某些概率比越界。
- PPO 的局部目标并不提供无条件单调提升保证。TRPO 的理论动机可作一句背景，不要把理论条件抹去。[^7]
- 复用的是近期轨迹上的有限次更新；这不意味着无限重复旧数据仍等价于 on-policy 学习。

工程上，Actor 损失通常还会配合 Critic 损失、熵项、KL 监控、梯度裁剪等。讲述时区分“PPO 的核心公式”和“具体训练配方”。

## 7. 语言模型如何成为策略

对提示 \(x\) 生成回答 \(y=(y_1,\ldots,y_T)\)：

\[
\pi_\theta(y\mid x)=\prod_{t=1}^{T}\pi_\theta(y_t\mid x,y_{<t}),\qquad
\log\pi_\theta(y\mid x)=\sum_t\log\pi_\theta(y_t\mid x,y_{<t}).
\]

把 token 当动作时，状态是提示和已生成前缀，转移通常是把 token 拼上去。也可以从任务层面把完整回答当作一次动作，把问题视为 contextual bandit。两种视角的用途不同：前者方便实现 token 级更新，后者帮助理解结果奖励；都不能自动证明存在外部多步交互。

### 7.1 SFT、RLHF 与 RLVR

| 方式 | 训练信号 | 数据怎样来 | 主要学习行为 |
|---|---|---|---|
| SFT | 示例回答的 token | 教师／标注者给示范 | 模仿示范 |
| 经典 PPO-RLHF | 学到的偏好奖励，常配参考策略约束 | 偏好标注 + 当前策略采样 | 提高奖励模型偏好的输出概率 |
| 标准 DPO | 同一提示下的偏好对 | 常为固定 chosen/rejected 数据 | 调整相对参考模型的偏好似然差 |
| RLVR | 验算、测试或形式化判定 | 题目 + 当前策略采样 + 验证器 | 提高可验证成功概率 |

“RLVR”描述奖励来源，并不是与 PPO 或 GRPO 平行的一种优化算法。规则也不一定完美：通过有限测试不等于程序在所有输入上正确。

### 7.2 经典 PPO-RLHF 的四个角色

InstructGPT 是连接偏好学习与 LLM 后训练的代表性论文：SFT 示范、偏好排序、奖励建模，再进行 RL 优化。偏好学习在深度 RL 中更早已有代表性研究。[^9][^10]

| 角色 | 功能 | 通常是否更新 |
|---|---|---|
| Actor／policy | 生成回答 | 更新 |
| Reference | 提供相对固定的行为参照 | 通常冻结 |
| Reward model | 给完整回答打偏好分 | 一个 RL 阶段内通常冻结 |
| Critic／value | 预测后续回报以估计优势 | 更新 |

角色数量不等于独立模型副本数量。LoRA、共享骨干、价值头和卸载都会改变内存布局。Reward model 判断输出质量；Critic 预测从当前前缀继续走的期望收益，二者不能互换。

一个常用的序列层面目标是

\[
\max_\pi\ \mathbb E_{x,y\sim\pi}[r_\phi(x,y)]
-\beta\mathbb E_x D_{\rm KL}(\pi(\cdot\mid x)\|\pi_{\rm ref}(\cdot\mid x)).
\]

实现常把参考策略的 log-prob 差作为 token 级代价，再与末尾奖励组合。**old policy 是当前批次的数据来源，reference policy 是长期参照**；它们可在初始时相同，概念与更新节奏却不同。

## 8. DPO：偏好数据上的直接目标

从同类 KL 正则奖励最大化目标出发，在相应假设下，最优策略与奖励满足

\[
\pi^*(y\mid x)=\frac{1}{Z(x)}\pi_{\rm ref}(y\mid x)e^{r(x,y)/\beta}.
\]

改写为 \(r(x,y)=\beta\log\frac{\pi^*(y\mid x)}{\pi_{\rm ref}(y\mid x)}+\beta\log Z(x)\)。在 Bradley–Terry 偏好模型中比较同一个提示下的两个回答，配分函数项相消。以 \(y_w\) 为 preferred、\(y_l\) 为 dispreferred，得到

\[
L_{\rm DPO}=-\mathbb E_{(x,y_w,y_l)}\log\sigma\left(
\beta\left[
\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\rm ref}(y_w\mid x)}
-\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\rm ref}(y_l\mid x)}
\right]\right).
\]

标准 DPO 不需要另外拟合显式奖励模型，也不要求在每一步优化中进行在线 rollout。它与 RLHF 的目标联系密切，但它的常见训练形式是偏好数据上的直接优化，不应称为 PPO 的升级版或“在线试错算法”。[^11]

DPO 适合已有较可靠偏好对、目标主要体现为可比较输出偏好的任务。新的交互状态、在线探索不足和数据分布偏差，不会仅因采用 DPO 自动消失。在线构造偏好对的变体存在，但需要明确说明采样和数据更新过程。

## 9. GRPO：用同题多次尝试进行相对评价

### 9.1 直觉与教学版公式

同一道题采样 \(G\) 个回答，奖励为 \(R_1,\ldots,R_G\)。结果监督版本用组内比较构造优势：

\[
\bar R=\frac1G\sum_iR_i,\qquad
\hat A_i=\frac{R_i-\bar R}{\operatorname{std}(R_1,\ldots,R_G)+\varepsilon}.
\]

通常将该回答的结果优势广播到其生成 token。定义 token 概率比 \(\rho_{i,t}=\pi_\theta(y_{i,t}\mid x,y_{i,<t})/\pi_{\rm old}(y_{i,t}\mid x,y_{i,<t})\)，原始 GRPO 可教学性概括为：

\[
J_{\rm GRPO}=\mathbb E\left[\frac1G\sum_i\frac1{|y_i|}\sum_t
\left\{\min\left(\rho_{i,t}\hat A_i,\operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)\hat A_i\right)
-\beta\widehat D_{{\rm KL},i,t}\right\}\right].
\]

\(\widehat D_{\rm KL}\) 表示实现采用的参考策略 KL 估计项；不要把这张压缩公式当作所有库的精确定义。DeepSeekMath 引入 GRPO，讨论结果和过程监督，并使用奖励模型；“去掉 Critic”不等于“去掉所有奖励模型”。[^12]

### 9.2 一组数字足够讲清楚

奖励是 \([1,0,0,1]\)，使用总体标准差时，均值 0.5、标准差 0.5，优势为 \([1,-1,-1,1]\)。若使用样本标准差，数值幅度不同，排序与符号相同，实际复现需记录约定。

如果奖励全为 0 或全为 1，中心化结果优势为 0，通常没有这一部分的策略改进信号；KL、熵或其他辅助项仍可能有梯度。全错不自动告诉模型正确方法，全对也缺少同题内的比较信号。这解释了为什么任务难度、组大小、探索和课程设计常常决定训练能否开始。

### 9.3 R1、R1-Zero 与后续配方

DeepSeek-R1-Zero 从已预训练基座直接开展 RL，没有先做该阶段的 SFT；它绝不是从随机权重开始。DeepSeek-R1 使用冷启动数据和多阶段流程；R1 的蒸馏小模型也不能被称为每一个都独立复现了同一套 RL。该论文是解释推理训练的重要案例，不是“任何小模型都能靠纯 RL 长出通用推理”的保证。[^13]

2025 年的几个方法可以放在一张延伸表里，不必逐个推导：

| 方法 | 值得理解的问题 | 不宜过度概括 |
|---|---|---|
| DAPO | clip 上下界、有效样本、token 聚合、超长输出处理 | 不是只改一个损失名称就复现整套系统 |
| Dr. GRPO | 按输出长度和题内标准差归一化改变样本权重 | 不等于消除了 RL 的所有偏差与不稳定 |
| GSPO | 使用序列似然构造归一化比率，做序列级裁剪 | 不能把所有 token 级方法宣布为过时 |

DAPO 的四项配方见原文；Dr. GRPO 分析长度与题目难度相关的权重效应；GSPO 从序列级优化讨论稳定性。各论文只支持其研究设置下的实验结论。[^14][^15][^16]

## 10. 编程能力的 RL：先拆成两类问题

### 10.1 单轮函数或竞赛题

```text
题目与约束 → 策略生成多个候选程序 → 隔离执行测试
          → 奖励与失败类型 → 估计优势 → 更新策略 → 新候选
```

训练奖励可以是全测试通过的二值信号，也可以是通过测试比例。后者更密集，但模型可能只优化容易的子测试，因此仍需报告“整题全部通过率”。HumanEval 是功能正确性与 pass@k 讨论的经典入口，不能把评测集直接当训练题库。[^18]

执行环境需要区分语法错误、超时、资源耗尽、依赖故障与逻辑错误。测试代码和隐藏答案不应进入模型可读的任务区；模型不能通过改评测器取得奖励。这些是代码 RL 实验正确性的组成部分。

### 10.2 多轮仓库修复

```text
Issue + 仓库快照
  → 搜索文件 → 读取代码 → 修改 → 运行测试
  → 根据报错继续修复 → 提交补丁 → 隐藏验收
```

这里每个工具返回都会改变后续上下文。训练对象是包含多个决策点的轨迹，环境成本还包括容器重置、仓库安装和测试时长。SWE-bench 为这类问题提供了代表性评测定义，但具体版本、任务子集和代理框架必须随结果一起报告。[^19]

| 代表工作 | 数据与反馈 | 报告中应强调的区别 |
|---|---|---|
| SWE-RL | 软件演化记录；补丁与目标解的规则相似度奖励 | 可以用软件工程数据训练推理，不等于每一步都在交互运行测试 |
| DeepSWE | 多轮软件工程环境、工具操作与测试验收 | 训练环境和代理执行框架成为关键组成部分 |

SWE-RL 原论文报告 Llama3-SWE-RL-70B 在 SWE-bench Verified 上 41.0% 的结果；这是其当时设置的历史数字。DeepSWE 官方 2025-07-02 报告将 42.2% pass@1、71.0% pass@16 与 59% 带测试时扩展的结果分开呈现。这些不同口径不能直接拼成算法排名。[^20][^21]

## 11. 长程任务：新增困难与训练方法

### 11.1 长文本不等于长程交互

一次生成很长的推理文本，仍可能只收到一个最终答案奖励。外部多步任务则需要行动引起环境变化、读取新信息并改变后续决策。ReAct 是讲清“思考与行动交织”的好材料，但不能把采用 ReAct 提示格式当作已经进行了 RL 训练。[^17]

### 11.2 一条可以解释清楚的轨迹优化流程

1. 固定任务初态或一组可重复的初态，采集多个完整交互轨迹。
2. 保存每次策略生成的 token、行为策略 log-prob、工具输入输出、动作边界、结束原因、奖励和策略版本。
3. 在策略损失中标识可训练位置：工具输出与环境文本是条件信息，通常不作为策略采样动作来优化。
4. 采用终局回报、步骤奖励或价值函数估计优势；使用轨迹组比较时，控制题目与初态差异。
5. 用 PPO／GRPO 类更新，有限复用样本；异步采样时另外处理策略陈旧与推理／训练概率差异。
6. 在冻结环境、动作预算和隐藏任务上评估；分别记录环境故障与策略失败。

这是供理解的通用实现框架，不宣称所有工作使用完全相同的细节。RAGEN 通过可控环境研究多轮训练中的不稳定与轨迹设计，适合支撑“多轮交互新增了哪些问题”。[^22]

### 11.3 四类困难与对应设计

| 困难 | 现象 | 可研究的处理方式 |
|---|---|---|
| 稀疏反馈 | 大部分轨迹都失败 | 简单到复杂课程、有效初态、示范热身、辅助验证 |
| 信用分配 | 前面错误几十步后才暴露 | 价值估计、可验证子目标、步骤反馈；检查奖励是否改变目标 |
| 探索不足 | 重复同一失败路径 | 多样化起点与采样、监控熵、保留失败类型 |
| 系统成本 | GPU 等待慢工具／长测试 | 环境并行、异步执行、缓存可复用依赖；控制样本陈旧 |

步骤奖励尤其容易产生捷径：反复开关门得分、打印“任务完成”、只跑容易测试。奖励不能只因看起来“合理”就加入，必须检查它与最终成功是否一致。

### 11.4 与 AI 智能体研究的连接

对于 AI 与大模型研究，可以把重点放在代码生成、工具调用和多步任务完成。先用文字版或二维“钥匙—门—目标”环境隔离探索与信用分配问题，再研究代码仓库或其他工具环境中的决策。两类任务都需要明确可见信息、合法动作、反馈与重置方式；小型环境上的改善还需要在目标任务中重新验证。

MiniGrid DoorKey 提供现成的任务语义与环境，可作为多步决策的教学参考。两周实践中可以用它验证任务完成与布局泛化，也可以选择更贴近研究需求的小型代码或工具任务。[^34]

### 12.1 “RL 是否创造新能力”应怎样回答

2025 年的一项研究通过较大 \(k\) 的 pass@k 比较，认为其研究的 RLVR 设置更像提高成功路径的采样效率，并可能缩小某些采样覆盖范围。这个结果值得讨论，但有限采样不能证明基座在所有可能输出上绝对没有某种能力，也不能证明所有 RL 永远无法产生新能力。[^23]

对于本次实践，可检验且足够有价值的结论是：**同一测试分布、同一推理预算下，训练后任务成功率是否提高，是否保持泛化，以及成本有没有变化。** “从零获得推理”需要更强的实验设计，不是看到一条反思文本或一张奖励曲线就能下的结论。

## 13. 如何读一篇大模型 RL 论文

依次寻找：基座与初始化阶段；训练题目与数据泄漏控制；奖励来自规则还是模型；采样与更新算法；实际训练算力；推理框架和预算；评价指标；消融与重复实验。对“只用 RL”追问它从什么已有模型开始，对“超过某模型”检查温度、上下文、候选数和工具权限是否一致。

优先读公式旁边的变量定义、训练循环与评测设置，再读主结果图。结果漂亮但无法确认分母是什么、样本怎样采或测试怎样运行时，先保留判断。具体阅读顺序见《论文与资料导读》。
