# 长程 Agent 强化学习怎样实际训练

## 1. 与简单 PPO／GRPO 的关系

长程 Agent RL 的基本目标仍然是最大化交互轨迹的期望回报。它不必使用完全不同的优化算法；很多方案继续使用 PPO、GRPO 或其变体。真正新增的部分是：环境如何可重复执行，轨迹如何组织，动作和 token 如何获得信用，长任务如何并行收集，以及如何处理训练数据落后于当前策略的问题。

本专题主体按 2026-09-12 可核对的原始资料整理。2026-10-14 补充 [AlphaZero、单轮/多轮对照与近期 Agent RL 导读](10_从AlphaZero到多轮Agent强化学习.md)，加入 G2PO（2026-06）、ProVer（2026-09-28），并复核 FACTOR、DeepSWE、Agent Lightning 的方法边界。重点是可解释的训练机制，不对最新模型作能力排名，也不据此推断闭源产品未公开的训练细节。

| 维度 | 单轮结果奖励任务 | 多轮真实任务 |
|---|---|---|
| 输入 | 题目／提示 | 任务＋仓库／网页／工具环境初态 |
| 一条样本 | 一次回答 | 多次模型调用、工具执行与新观测 |
| 状态变化 | 自回归前缀增长 | 外部环境变化、信息发现、失败与恢复 |
| 奖励 | 最终答案正确性 | 最终产物验收，可能另加步骤信号 |
| 优势 | 单回答结果或 token 价值 | 整轨迹、调用级、动作级或 token 级估计 |
| 生成成本 | 主要是模型推理 | 还包括执行、安装、测试、等待和重置 |
| 数据格式 | prompt/completion | 实际上下文、动作、反馈、版本、边界等 |
| 常见新增问题 | 长输出与全零组 | 信用分配、部分可观测、慢环境、上下文重构、样本陈旧 |

“把 GRPO 加上工具调用”可以是第一版，但不是完整训练系统。

## 2. 长时间、长文本、长决策链是三个量

需要分别记录：墙钟时间 W、生成／上下文 token 数 L、环境决策次数 K。

- 生成一个命令，等待一小时训练完成：W 很长，K 可以很小。
- 连续输出三万 token 的推理：L 很长，不一定有外部交互。
- 查信息、改计划、调用工具、恢复错误一百轮：K 很长，状态与信用分配都复杂。

墙钟时间长本身不需要保存一小时的反向传播图。策略梯度可在事后重放保存的模型输入与动作，重新前向求 log-prob。真正困难是获得足够完整样本、保留正确决策上下文，以及让很早的行动得到有用反馈。

若目标关心耗时，可以加入明确的时间成本，或用 semi-Markov 形式按动作持续时间定义折扣。若只关心规定期限内的成功率，就不应无意中把每秒都当一个折扣步，导致耗时任务的成功奖励几乎归零。奖励时间尺度必须对应实际目标。

## 3. 一次代码修复任务怎样变成 RL 数据

以下是教学任务，不是某篇论文的原始轨迹：修复一个函数在空输入时崩溃的问题，同时不能破坏其他输入。

```text
初始化：Issue + 指定仓库 commit + 可执行依赖 + 隐藏验收器

模型调用 1：search("parse_items")
环境返回 1：文件路径与匹配片段
模型调用 2：read_file("parser.py")
环境返回 2：源码
模型调用 3：edit_file(...)
环境返回 3：编辑完成
模型调用 4：run_tests(...)
环境返回 4：空输入通过，但一般输入回归失败
模型调用 5：edit_file(...)
环境返回 5：编辑完成
模型调用 6：run_tests(...)
环境返回 6：可见测试通过
模型调用 7：submit()
隐藏验收：补丁是否修复缺陷且通过回归测试
```

### 3.1 采样器必须做的事

每次模型调用都保存实际输入上下文、输出 token、采样策略版本及 token log-prob。工具输出、结束原因、耗时和环境快照信息单独保存。只留一份最终聊天记录通常不够：中间可能发生过上下文截断、摘要或模板替换。

同一个任务从相同初态独立尝试多次，形成成功和失败轨迹。比较时固定工具接口与验收规则；若环境随机，需要记录种子或把随机性纳入统计分析。

### 3.2 奖励来自可验收结果

第一版可以只使用终局 0/1：提交的补丁通过隐藏验收记 1，否则记 0。不能奖励“模型说已完成”，也不能让模型修改隐藏评分逻辑。

训练用的快速测试可以是代理反馈；最终评价应有独立完整验收。语法错误、逻辑失败、合法任务超时和容器故障要区分。策略在任务预算内未完成可以是真实失败，执行机器故障却可能只是不可用数据，不能自动混成同一种惩罚。

这一步是环境与数据工程，不是 PPO 公式能够替你决定的内容。

## 4. 最小多轮 GRPO：一条轨迹一个结果优势

对同一个任务 x 采样 G 条完整轨迹 \(\tau_i\)，得到结果 \(R_i\)。从组内比较得到 \(\hat A_i\)。设第 k 次模型调用生成 \(u_{i,k}\)，第 l 个生成 token 的条件上下文为 \(c_{i,k,l}\)。

轨迹中的可训练策略 log-prob 是

\[
\log\pi_\theta(\tau_i\mid x)
\ \text{的策略部分}=\sum_k\sum_l\log\pi_\theta(u_{i,k,l}\mid c_{i,k,l}).
\]

环境转移因子不进入对 θ 的直接求导。对每个生成 token 定义概率比

\[
\rho_{i,k,l}=\exp\big(\log\pi_\theta(u_{i,k,l}\mid c_{i,k,l})-
\log\pi_{\rm behav}(u_{i,k,l}\mid c_{i,k,l})\big).
\]

一个最小的教学目标是将所有调用的 token 送入

\[
\sum_{k,l}\min\left(\rho_{i,k,l}\hat A_i,
\operatorname{clip}(\rho_{i,k,l},1-\epsilon,1+\epsilon)\hat A_i\right),
\]

再对轨迹与任务聚合，可另加参考策略正则。具体归一化属于算法配方：按轨迹平均、按调用平均、按有效 token 数或固定长度缩放会改变样本权重，不能省略不说。原始 GRPO 与多轮扩展的出处见 DeepSeekMath、RAGEN 和 DeepSWE。[^1][^2][^3]

### 4.1 与单轮版本最直接的差别

奖励从“一次回答”变成“一次完整任务”。参与训练的 token 来自多次模型调用，中间夹着环境观测。每个动作的条件还包含先前工具结果，所以训练可以改变模型如何根据测试报错选择下一次修改，而不是只学一个静态补丁字符串。

### 4.2 不能优化环境 token 的概率

若把整条聊天轨迹拼接训练，需要 action loss mask，屏蔽用户消息、工具返回等非策略输出。若按调用拆成 input/output 样本，则只训练当次 output token，input 作为条件。两种组织形式都必须忠实重建采样上下文。

工具输出仍能通过后续动作的条件表示影响网络梯度；“屏蔽”指它不是被采样的动作标签，不能理解成环境信息与学习完全无关。

### 4.3 为什么如此粗的信号也能起效

如果“查看相关测试再修改”的轨迹更常成功，策略梯度在大量轨迹上可以提高这种决策的发生概率，不需要人为逐步标注。但终局优势也会强化成功轨迹中的无用动作，短期内无法精确区分贡献；当成功极少、轨迹极长或各次尝试几乎一样时，信号会很弱。

因此这一方案能作为基线，不能被说成解决了全部长程信用分配。

## 5. 更精细的信用分配究竟改变什么

### 5.1 调用级 Critic：回到 Actor–Critic

以每次调用前的历史／状态 h_k 为输入，训练 \(V_\phi(h_k)\) 或 \(Q_\phi(h_k,u_k)\) 预测后续结果。调用级 TD 误差为

\[
\delta_k=r_k+\gamma(1-d_k)V_\phi(h_{k+1})-V_\phi(h_k).
\]

它可用于 TD／GAE，形成各次调用不同的优势，再分给调用内部 token。下面的价值数字完全是教学假设：

| 调用 | 动作前 V | 动作后 V | 即时奖励 | γ=1 的 TD 误差 |
|---|---:|---:|---:|---:|
| 定位相关文件 | 0.1 | 0.3 | 0 | +0.2 |
| 找到关键测试 | 0.3 | 0.8 | 0 | +0.5 |
| 引入错误修改 | 0.8 | 0.6 | 0 | -0.2 |
| 修复回归 | 0.6 | 0.9 | 0 | +0.3 |
| 成功提交 | 0.9 | 0 | 1 | +0.1 |

终局成功不妨碍某步 TD 误差为负。但这个 TD 数字依赖价值估计，并非该动作的真实因果贡献；若用 λ=1 的完整 GAE，后续正项又会加回来，得到对应的 Monte Carlo 回报减 V。必须说明使用的是一步 TD、GAE 还是其他分配方法。

ArCHer 是很适合精读的桥梁：在 utterance 层使用可复用数据的价值学习，把高层价值用于 token 策略优化。它说明“高层调用评价”和“低层 token 生成”可以用不同时间尺度，不要求把每个 token 都当成一个外部环境步骤。[^4]

### 5.2 中间验证与奖励塑形

给可独立验收的子目标提供反馈，例如某个中间文件正确生成、某项测试由失败变成通过。好处是缩短反馈延迟；代价是新增代理目标和被利用的可能性。连续打印进度、重复通过同一个简单测试，不应产生无限奖励。

潜势式塑形可以写成 \(r'_k=r_k+\gamma\Phi(h_{k+1})-\Phi(h_k)\)。在相应 MDP、折扣与终止边界条件下，它的累计附加项可望远镜消去；这说明有些塑形能保留原任务目标。但有限回合的终端潜势等条件必须处理正确，不能把任意步骤奖励都称为策略不变。[^10]

### 5.3 从关键中间状态分叉重试

保存一个关键时刻的环境快照，分别尝试不同决策或从该状态多次继续执行，估计后续成功率。这样可以给 Critic 更有针对性的训练信号，也能比较某个决策后的前景。

代价是更多环境执行，而且需要能恢复真实状态。文件系统、浏览器会话、外部数据库和异步任务未必都能安全、完整地回滚。没有反事实采样，不应把仅阅读一条成功轨迹得到的“逐步评分”直接称为严格因果归因。

### 5.4 2026 年两条具体研究线索

**ΔBelief-RL** 以模型对目标答案的信念变化构造中间反馈，并进行 turn-wise 相对优势估计。它适合研究“如何学会提问和获取信息”。使用真实目标进行训练侧评分，不代表 Actor 在决策时可以看到目标答案；信念分数与真实进展之间仍需验证。[^5]

**FACTOR** 把“各行动分多少信用”和“行动内部哪些 token 分到信用”分开，使用经中间快照续跑校准的 TD 行动信用，以及带反馈的 token 分配，并控制聚合时的长度权重。它是近期预印本，本文只用来说明方法细节正在向两个时间尺度发展；未独立复现其性能，也不将其称为统一最优解。[^6]

### 5.5 2026-10-14 补充：轨迹图与关键片段验证

G2PO 将同任务多条轨迹中的相同观测聚合为状态图，组合轨迹、节点与边上的优势，沿用 GRPO 风格裁剪更新。ProVer 则让 judge 提议关键片段，再从片段前后恢复状态并续跑，用成功率差验证局部价值，向选中片段增加正的优势信号。前者依赖观测分组的合理性，后者依赖状态恢复且有额外交互成本；都不等于对每个动作获得无条件准确的因果贡献。原文与教学例子见 [10 专题 §5–6](10_从AlphaZero到多轮Agent强化学习.md)。

## 6. 两种轨迹组织方式：拼接与按调用拆分

| 组织方式 | 实现方式 | 优点 | 需要检查 |
|---|---|---|---|
| 整条对话拼接 | 保留角色消息，对策略输出做 loss mask | 对追加式对话容易理解 | 长度、角色／位置、截断与 mask 一致性 |
| 按调用拆分 | 每次实际 input/output 独立作为训练 transition | 适配摘要、角色切换与复杂工作流 | 不能丢失原上下文；避免前缀动作被重复计损失；明确调用权重 |

按调用拆分并不意味着只训练一次调用的短期目标；该调用的学习系数仍可来自整个任务的终局回报。它改变训练数据的组织，不自动解决信用分配。

Agent Lightning 的原文 §3.3.2 明确：它先给各调用分配回报，再使用已有单轮 RL 方法训练 token；其当时实现给每个调用同样的最终回报 R，更复杂的高层价值分配作为后续扩展。**这是执行与训练解耦的例子，不是已经获得精确逐动作信用的证据。**[^7]

完整轨迹超出上下文时，可以分块或重建各调用的实际输入。若某次原始调用本身已超出模型支持长度，不能通过随便截掉前文后仍声称在计算同一个行为条件下的 PPO ratio。训练时的输入必须与记录的行为概率含义一致。

## 7. 很长时间的任务，系统怎样持续训练

### 7.1 完整回合不等于完整计算图

常见方案是：执行进程把轨迹写入持久存储，完成或达到定义的结束条件后送入训练队列。GPU 在回合执行期间不需要保留所有旧激活；训练时重新做前向计算，可以配合梯度检查点、微批次和分段样本。

尚未得到终局结果的部分轨迹，可以先保存或使用经过定义的 bootstrap 目标。不能既截断又把“未知未来”任意标成零，声称仍在优化原来的长期成功目标。环境真正终止、用户期限耗尽、训练侧截断和机器故障必须分开。

### 7.2 异步采样、队列与样本陈旧

若一批任务有的十秒、有的半小时，同步等待最慢任务会降低利用率。可以让多个 rollout worker 持续执行任务，训练进程按可用数据更新，再向采样器同步权重。

问题是：这批数据可能来自多个旧版本，甚至一条长轨迹不同片段用过不同版本。必须保存真实行为策略的 log-prob，限制陈旧程度或使用适当校正，而不是把分母都伪装成最近的统一 old policy。

AReaL 把行为策略与近端约束参照分开，并控制异步数据陈旧。其原论文的主体实验是数学和代码推理，用于说明异步系统机制；不能把它的系统加速结果直接描述为“小时级真实 Agent 能力提升”。[^8]

### 7.3 训练期间稳定，部署期间也要稳定

一个可解释的首轮实验可以让每条轨迹使用固定策略快照，先收完整回合再更新。大规模异步实现可以更复杂，但要有策略版本协议。

长程 Agent 在执行用户任务时，不必边做边更新权重。常见流程是训练期在大量任务上迭代，部署期固定策略执行；记忆更新、计划调整和上下文反思都可能发生在固定权重下。持续在线学习是额外系统设计，不是“能做长任务”的定义。

## 8. DeepSWE：把算法与工程连起来的具体案例

DeepSWE 官方 2025 年技术报告提供了一个可讲清的实例：从 Qwen3-32B 开始，在 R2E-Gym 软件任务中执行搜索、编辑、命令和提交；使用测试结果给终局奖励；对多轮轨迹中的环境观测做 mask，再用修改过的 GRPO 配方更新。它还明确讨论了最大步数、超长与超时轨迹的过滤，以及 rollout 容器调度。[^3]

相对“原始 GRPO”应讲的三项变化：

1. **交互闭环：** 每个样本包含多次工具调用，最终评分的是补丁产物。
2. **估计与稳定性：** 调整裁剪、奖励标准差与长度归一化，并使用 leave-one-out 等配方。
3. **执行和结束规则：** 定义提交、超时及截断轨迹怎样进入损失。

这些是该工作的一套选择，不是所有 Agent RL 的标准。尤其过滤超时样本会改变训练分布，其他任务可能应该对预算耗尽给失败奖励；先定义产品目标，再决定过滤策略。

R2E-Gym 提供可执行任务环境，其原始工作还使用成功轨迹 SFT 与测试时 verifier。**环境论文、SFT、在线 RL、测试时择优是不同环节**，不能只看到“Agent 变强”就把所有收益归为 RL。[^9]

## 9. 一套可落地的最小训练流程

下面是设计方案，不是已完成的大模型训练：

```python
for iteration in training_loop:
    behavior = frozen_snapshot(policy)
    tasks = sample_training_tasks()
    grouped_trajectories = []

    for task in tasks:
        # 每次独立重置；这些完整回合实际可以并行执行
        group = [run_agent(behavior, reset(task)) for _ in range(G)]
        # run_agent 保存各次实际 input、output、行为 log-prob、工具反馈与边界
        rewards = [hidden_acceptance(traj.final_artifact) for traj in group]
        advantages = compute_group_advantages(rewards)
        grouped_trajectories.append((group, advantages))

    batch = build_call_level_samples(grouped_trajectories)
    # 最小版：各调用使用其所属轨迹的结果优势；明确聚合权重
    # 进阶版：调用级 Critic / GAE 替换这部分估计
    for _ in range(limited_update_epochs):
        new_logp = policy.log_prob(batch.actual_inputs, batch.sampled_outputs)
        ratio = exp(new_logp - batch.behavior_logp)
        objective = ppo_clip(ratio, stop_gradient(batch.advantage))
        loss = -declared_reduction(objective, batch.action_mask)
        update(policy, loss)

    evaluate_on_validation(policy, fixed_tool_and_budget_config)
```

实施顺序：先确认环境与奖励可用；保存一批完整轨迹并人工核对；跑最小多轮 GRPO；识别全零组、循环调用、长度增长与截断；再决定是否引入 Critic、步骤反馈或异步。这样能区分问题来自哪个部分。

### 9.1 如果根本采不到成功，梯度从哪里来？

对于只有终局 0/1 奖励的组内相对优势，全组失败或全组成功时，结果奖励对应的优势为零；如果还加了 KL 等项，它们仍可能产生更新，但没有提供这个任务中哪条轨迹更好的结果信号。

假设同一任务各次独立尝试的成功率为 p，一组 G 次同时包含成功与失败的概率为 \(1-p^G-(1-p)^G\)。若 p=1%、G=8，约 92.3% 的组全失败。增加候选数能改善发现成功的概率，但执行成本也随之增长；它不能替代可学的任务分布。

本次实践可先使用更短的任务、缩小仓库、提供可控的初始线索，或用成功轨迹 SFT 热身，再逐渐撤去辅助并增加依赖链。可验证的中间目标也是候选办法，但会改变反馈设计。这些是实验设计建议，不是已经验证有效的本项目结果。Critic 可以复用已有反馈，却不能凭空知道从未观察到的成功路径；奖励与探索不足不能只靠换一个优势公式解决。

多 Agent 工作流还需要为各模块标记角色和策略版本。多个 Agent 同时更新会使彼此成为非平稳环境；固定其他模块或交替更新是可研究的起点，不应仅把所有消息混在一起求 loss。

## 10. 能力提升应体现在哪些行为与指标

RL 可能改善的是：更有效地查信息、根据报错纠正、选择何时验证、减少无效循环、正确结束任务。这些行为应作为可测指标或案例解释，不能只由训练后文本里的“我会仔细检查”推断。

主指标仍是**留出真实任务上的最终验收成功率**，并固定模型可用工具、每次任务的 token／动作／时间预算和候选数。另列：首次成功时间、P50/P95 耗时、工具调用次数、错误恢复率、循环率、预算耗尽率、环境故障率与成本。

做“长程”评价时，应按实际决策跨度、依赖深度或外部任务难度分层，不能只按模型自己跑得多长划分；否则糟糕策略反复绕圈也会被当成长任务。

至少比较：同一起点模型、相同 scaffold 的 RL 模型、成功轨迹 SFT、增加推理预算的起点模型。按仓库／任务族划分数据，保留与训练不同的初态或环境版本。给出题目层不确定性与训练 seed 差异，防止把更多候选采样当作更多独立训练复现。

## 11. 对本次实践的调整

数字组合游戏适合快速掌握策略梯度与训练循环，但不能作为长程 Agent 能力提升的主证据。根据当前重点，建议采用两级实践：

**机制演示：** 使用三动作解析例子，核对梯度、baseline 和单次更新的随机性。已提供标准库脚本；这部分几秒即可重复运行，不需要显卡。

**正式训练候选：** 一个小型代码修复环境，限制工具为搜索、读文件、修改、测试、提交，任务必须通过反馈才能稳定解决，初期控制在数次到十余次调用。先尝试轨迹级结果优势，再按实际瓶颈选择调用级 Critic 或可验证步骤反馈。

这一调整优先贴近研究问题，是否能在两周完成仍取决于算力、初始成功率和环境准备。可以缩小任务族与调用次数，不需要故意加等待来制造“长时间”；日后再增加真实依赖链、难度与时长。
