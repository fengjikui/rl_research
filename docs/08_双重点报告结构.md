## 三个最重要的过渡

**策略梯度到 Actor–Critic：** “方向已经知道怎样估计，但一次结果太随机。我们能不能预测从当前状态继续的前景，得到更有效的比较信号？”

**Actor–Critic 到 PPO：** “现在有了优势估计，但采样昂贵。怎样复用这批经验，同时避免一次把行为分布改得太远？”

**单轮 RL 到 Agent：** “梯度公式没有忘记。现在一次成功来自七次模型调用、六次外部反馈与二十分钟执行；先决定这七次调用如何得到学习系数，再讨论优化器。”

## 数值演示

运行 [policy_gradient_check.py](../examples/policy_gradient_check.py) 展示三件事：解析梯度与有限差分一致；不同动作独立 baseline 保持同一个期望梯度；精确小步梯度提高目标，但某个单样本估计可以降低目标。

该脚本只依赖 Python 标准库。它证明的是这个可枚举玩具例子中的数学关系，不作为 LLM 或 Agent 能力提升证据。

现场不需要展示整个 JSON。只保留初始概率、奖励、精确梯度更新前后的期望得分，以及单样本下降的对照。特别指出 softmax 联合归一化和参数共享，避免把 logit 的变化与每个动作概率的变化混为一谈。

## 实践如何服务这两个问题

解析例子负责第一部分的机制；正式实验优先考虑有固定工具接口的小型代码修复 Agent，负责第二部分的经验。数字组合训练保留为资源不足时掌握框架的暖场，不能代替多轮任务实验证据。

正式 Agent 实验先使用终局验收与最小轨迹级 GRPO。只有诊断表明均匀信用、全零组或工具成本成为瓶颈后，再选一个改进点；两周内不同时叠加多个新算法。训练硬件仍待确认，尚未开展语言模型训练。

## 问答准备

1. 为什么不能直接对 0/1 奖励调用 backward？
2. 一个动作只在偶然成功的轨迹中出现，会不会被错误强化？
3. 有正确 baseline 时为什么单次更新仍可能变差？
4. Critic 的误差会不会传给 Actor？哪些地方应该 detach？
5. PPO 的 old、reference、异步行为策略分别指什么？
6. 全组失败时，GRPO 为什么不知道该改哪里？
7. 按调用拆分轨迹是否就自动得到精确信用？
8. 一个小时任务是否需要保存一个小时计算图？
9. 遇到上下文压缩、工具故障和预算耗尽，如何构造正确样本？
10. 如何区分 RL 的改善、成功轨迹 SFT 的改善和更多推理预算的改善？
