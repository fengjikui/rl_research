# 国庆强化学习学习路线与讲解练习

更新：2026-10-14。本文是当前学习入口；之前的教程、推导和实验继续保留。目标是建立可解释、可运行、可评价的知识体系，不以一周覆盖所有强化学习研究分支为完成标准。新增 [AlphaZero 与多轮 Agent RL 专题](10_从AlphaZero到多轮Agent强化学习.md)。

## 资源与学习方式

用户已有完整昇腾 A3 节点服务器。具体设备、卡数、设备内存、系统及软件版本、可用配额和访问方式尚未核验，尚未连接该服务器。实验先通过小规模正确性检查，再按资源与吞吐扩展，不预设必须使用完整节点。

每个主题采用四步：看一个实际行为；解释数据和损失；做一个小实验；由用户用 3–5 分钟讲解，助手作为听众追问并反馈。每次只追问一两个关键缺口，避免一次覆盖所有细节。

讲解评议分别关注：

- 正确性：术语、公式与因果关系是否准确。
- 完整性：是否说明输入、输出、反馈、更新和评价。
- 清晰度：听众能否复述，例子能否支持结论。
- 内容价值：听众因此理解了什么，哪些信息可以删减。
- 证据边界：有没有把训练分数、同分布测试或个别成功案例说成通用能力。

反馈格式：先复述听到的核心观点，再指出最重要的一处问题，提出一个检验理解的问题，最后给出可用于报告的修改建议。允许用户先完整讲完再反馈。

## 八个可拆分的学习单元

这些是学习单元，不要求每天完成一个；可配合其他项目，每次安排 60–90 分钟，额外实验另排。

| 单元 | 主问题与实例 | 当次产出 |
|---|---|---|
| 1 游戏与交互 | 用接球解释闭环，用 Atari Breakout/DQN 展示经典成果，用 DouZero 展示隐藏信息与合作 | 一段 3 分钟开场；把一次游戏映射到 RL 概念 |
| 2 价值学习 | Q 表、蒙特卡洛、TD 与 DQN 的训练目标如何不同 | 手算一个更新；读已有 DQN 接球代码 |
| 3 策略梯度 | 为什么提高高回报动作的 log-prob；baseline、Actor-Critic、优势 | 手算二动作策略；说明为什么奖励本身不必可微 |
| 4 稳定更新 | PPO 的旧策略、比率、裁剪；GRPO 的分组优势与全同分组 | 对照共享损失代码；解释哪些张量停止梯度 |
| 5 语言模型 | RLHF 的偏好反馈、奖励模型、PPO；可验证奖励与 GRPO；DPO 作分支 | 一条 prompt→采样→评分→更新→独立测试的完整链条 |
| 6 多轮 Agent | DeepSWE 的轨迹与验收、ProVer 的局部信用；G2PO/FACTOR 作深入阅读 | 讲清工具观测 mask、完整轨迹优势和中间状态续跑 |
| 7 具身智能 | 从摆杆/到达目标到行走，连续动作、控制频率、奖励与仿真迁移 | 一张游戏/LLM/机器人对照表；解释策略输出怎样作用到身体 |
| 8 综合讲解 | 复盘实验、长程 Agent 与具身任务的联系、报告取舍 | 90 分钟讲稿的选材与一次问答演练 |

## 案例选材与边界

1. **Atari DQN**：适合展示从图像观察到离散动作的经典学习闭环。阅读 [Human-level control through deep reinforcement learning, 2015](https://www.nature.com/articles/nature14236)。教学代码先用仓库中的低成本接球环境，不把接球结果称作 Atari 复现。
2. **DouZero**：适合说明游戏模拟器、合法动作、部分可观测、自我博弈和农民合作。算法是 DMC，不能把它称作 DQN 或策略梯度。参考 [论文](https://proceedings.mlr.press/v139/zha21a.html) 与 [训练仓库](https://github.com/kwai/DouZero)。当前仓库未实测部署 DouZero。
3. **InstructGPT**：用于介绍人类偏好数据、奖励模型和 PPO。[原论文](https://arxiv.org/abs/2203.02155)。RLHF 描述反馈来源与训练流程，PPO 描述优化方法。
4. **DeepSeekMath**：用于介绍 GRPO 的组内比较与不单独训练 Critic 的设计。[原论文](https://arxiv.org/abs/2402.03300)。GRPO 不等同于 RLHF，也不要求奖励一定来自人；使用程序可核验奖励时应说明奖励来源。
5. **ANYmal 行走**：用于理解大规模仿真、课程训练和机器人落地。[Learning to Walk in Minutes Using Massively Parallel Deep Reinforcement Learning](https://arxiv.org/abs/2109.11978)。论文中的设备与并行仿真性能不代表昇腾服务器上的实际性能。

## 概念只在需要时引入

以接球为例：环境负责球和挡板的运动与判分；智能体是选择挡板动作的策略；观察是智能体获得的信息；动作是左移、停留或右移；奖励是当下反馈；回报是从某时刻起的折扣奖励总和；轨迹是观察、动作、奖励等组成的序列。状态指描述环境演化所需的信息，不总等于玩家可见观察。

第一次只讲闭环和这些词。下一次再引入 Q、价值、优势、折扣和 bootstrap。要区分轨迹长度、回报数值和运行耗时。

## LLM 实验与评价

已有实验：`grpo_lab/RESULTS.md` 记录 Qwen2.5-0.5B-Instruct 四位数字反转由 113/256（44.1%）到 236/256（92.2%）。这是已保存报告中的窄任务结果，本次未重跑；不能推导一般数学、编程或 Agent 能力都提高。

新候选优先考虑有自动判分的短任务：受约束输出、短程序修复/补全、有限多步计算。先在开发集测量基础成功率和奖励可靠性，再冻结任务规则；不为获得漂亮曲线删掉难题。选择模型尺寸应同时考虑昇腾适配、训练/生成吞吐和模型在任务上是否留有提升空间。

“80%→90%”是示例目标，不保证结果。前后固定测试集、提示词、生成预算与解码设置，统一使用 pass@1 等口径。训练、调参与检查点选择使用独立训练/验证数据，最终测试不得反复指导选择。报告样本量、配对变化及不确定性；资源允许时增加训练种子，并与等数据或等预算 SFT 基线比较。代码任务需隔离执行，隐藏测试不进入奖励或训练上下文。

## 昇腾实施路径

先核验节点设备信息与空闲资源，再确认驱动、固件、CANN、PyTorch、torch_npu/TorchNPU 和生成后端版本匹配。参考 [华为安装说明](https://www.hiascend.com/document/detail/en/Pytorch/2600/configandinstg/instg/docs/en/installation_guide/installation_description.md) 与 [verl 昇腾指南](https://verl.readthedocs.io/en/latest/ascend_tutorial/zh/get_start/install_guidance.html)。这些是当前候选资料，不代表已经测试该机器兼容性。

实施顺序：单设备前向与反向→生成与重算 log-prob 一致性→一个完整 GRPO 小批次→保存恢复→多设备扩展。手写实现用于讲原理，工程框架用于规模训练，避免把框架部署问题混进算法第一课。

具身智能需要另核验物理仿真器与渲染依赖。NPU 训练支持不等于支持依赖 CUDA 的 GPU 仿真；初期可选择 CPU 物理仿真与小模型，之后再决定异构部署。未验证前不承诺整节点可以直接运行某个机器人工具链。

本机继续执行负载、可用内存与热状态保护；高负载前和运行中采样、保守并发，必要时暂停自己的任务，不影响用户其他进程。

## 90 分钟报告建议

| 内容 | 分钟 |
|---|---:|
| 经典游戏与基本概念，加入 AlphaZero 对照 | 12 |
| 从价值学习到策略梯度、Actor-Critic、PPO | 23 |
| LLM 的 RLHF、GRPO 与实测结果 | 20 |
| 多轮 Agent：DeepSWE 与 ProVer | 15 |
| 具身智能中的控制、仿真与迁移 | 12 |
| 问答 | 8 |

DQN、DPO 和多轮 Agent 的进一步算法细节放备份；保留 15 分钟讲真实交互与近期信用分配方法。学习可以全面，报告需要选择；主线始终是：策略怎样从交互反馈中获得可验证的行为改善。

## 第一次讲解练习

用户用接球或斗地主讲 3 分钟，暂不使用算法名称，回答：谁在做决策、看到什么、能做什么、何时获得反馈、怎样知道它真的学得更好。助手听完后再纠错与追问。下一轮由助手根据暴露的缺口选择讲状态/观察、奖励/回报或训练/评价的区别。
