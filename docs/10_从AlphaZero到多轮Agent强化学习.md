# 从 AlphaZero 到多轮 Agent：训练对象、轨迹与信用分配

核对日期：2026-10-14。本文补充当前报告路线。选取机制清晰的代表性工作，包含 2026-09-28 的预印本，不声称穷尽截至今日的所有新论文。已阅读下列原始来源的方法部分；未复现这些工作，也未在昇腾节点启动训练。

## 1. AlphaZero 不是 DQN

AlphaZero 的核心组合是策略/价值网络、蒙特卡洛树搜索（MCTS）和自我对弈。网络输出落子先验 p 与局面预期结果 v；MCTS 用它们引导搜索，形成搜索后的落子分布 π；自我对弈得到终局结果 z。网络训练目标为：

\[
L(\theta)=(z-v_\theta(s))^2-\sum_a\pi_{\mathrm{MCTS}}(a\mid s)\log p_\theta(a\mid s)+c\|\theta\|^2.
\]

价值头拟合终局结果，策略头拟合搜索产生的分布。搜索不是通过反向传播求导的模块；它产生训练目标。具有策略头和价值头，也不等于使用 PPO 式 Actor-Critic 更新。

对比 DQN：后者学习 Q(s,a)，以奖励加下一状态最大动作价值构造 TD 目标。AlphaZero 的搜索过程也有动作价值统计，但不是 DQN 的 Q 网络/TD 训练配方。有限预算的搜索不保证每个局面都更优。

讲述价值：它展示了“搜索帮助产生更好的决策目标，网络学习这些目标，再帮助后续搜索”的循环。棋类有已知规则、可复制局面和精确胜负反馈；真实网站和物理环境不一定能同样廉价地复制、分叉和回滚。

来源：[AlphaZero 原论文，方法与式 (1)](https://arxiv.org/pdf/1712.01815)；[DeepMind 2018 年介绍](https://deepmind.google/blog/alphazero-shedding-new-light-on-chess-shogi-and-go/)。

## 2. 从 InstructGPT 到 Agent RL：到底改变了什么

先分清三个轴：Agentic 指会选择行动并利用外部反馈；多轮指多次交互；长程指早期决策影响较晚结果。通用性另指能否迁移到未见任务、工具和领域。这些性质不能互相替代，单一基准提高不能证明通用智能。

| 维度 | InstructGPT 的经典 RLHF 配方 | DeepSeekMath / R1-Zero 的相关配方 | 多轮 Agent RL |
|---|---|---|---|
| 一次训练尝试 | 给定提示后生成回答 | 同题生成推理与答案 | 从环境初态开始，多次行动、接收反馈，直到结束 |
| 反馈来源 | 人类偏好训练出的奖励模型 | DeepSeekMath 使用学习的奖励模型；R1-Zero 使用规则准确性/格式奖励 | 测试、数据库状态、任务验收，也可结合学习的评分器 |
| 优化方法 | PPO，学习价值估计，参考策略约束 | GRPO 的组内相对优势，无单独 Critic | 可继续用 PPO/GRPO/DAPO 等，或改变步骤/片段优势 |
| 输入如何变化 | 模型生成的 token 逐渐追加 | 同左，生成可以很长 | 还包含外部工具返回、环境变化、历史摘要 |
| 新的主要困难 | 偏好奖励可靠性与优化稳定性 | 探索、全同分组、长度与奖励 | 信用分配、执行成本、可重置性、上下文与策略版本一致性 |

这张表比较典型训练配方，不意味着单轮生成在 token 层没有序列决策。

GRPO 在 DeepSeekMath（2024）中提出；DeepSeek-R1（2025）进一步展示推理 RL 的效果。GRPO 去掉的是单独训练的价值 Critic，不意味着不能使用奖励模型。DeepSeekMath 还研究过程奖励，不能把所有 GRPO 统一描述成只有终局 0/1。R1 完整管线也不能缩写成 R1-Zero 的规则奖励阶段。

来源：[InstructGPT](https://arxiv.org/abs/2203.02155)、[DeepSeekMath §4](https://arxiv.org/html/2402.03300v3)、[DeepSeek-R1 §2.2–2.3](https://arxiv.org/html/2501.12948v1)。

## 3. 一条真实交互轨迹怎样采集

下面是教学设计，非论文原始样本：让模型修复一个空列表引发的崩溃。

```text
任务与初态：issue + 固定仓库版本 + 已装依赖 + 验收器
模型：搜索相关函数
工具：返回位置
模型：读取实现及测试
工具：返回源码
模型：修改文件
模型：运行可见测试
工具：边界测试通过，但回归测试失败
模型：根据失败反馈重新修改
模型：运行测试并提交
验收器：最终补丁是否通过保留测试，给出奖励
```

任务集合不必自带标准操作轨迹。先准备可以执行和验收的任务，再由当前策略在线交互生成轨迹；成功与失败都保留。示范数据或强模型轨迹可用于 SFT 热身，但那是另一种数据用途。

最小 GRPO 采集器对同一任务初始化多个独立环境，使用固定策略快照分别尝试。每次模型调用记录：实际输入 token、输出 token、采样设置、行为 log-prob、策略版本、工具参数与返回、结束原因。另记环境版本、初态/随机种子、时间与最终奖励。任意旧聊天日志不能直接当成严格 on-policy PPO 数据。

真实代码任务通常在可重置沙箱中运行真实程序；购物或室内任务可能使用可控模拟环境。必须说明实验属于哪种“真实”。训练时的回放不应要求重新对生产服务执行操作。

## 4. 这些轨迹如何用于更新参数

设一个任务获得四条独立轨迹，终局奖励为 [1, 0, 1, 0]。最简单的结果监督 GRPO 使用：

\[
A_i=\frac{R_i-\overline R}{\operatorname{std}(R)+\epsilon}.
\]

若用总体标准差并忽略很小的 ε，此例优势约为 [1, -1, 1, -1]。一条轨迹可包含多次模型调用；最简单版本把该优势赋给所有策略生成 token。它不等价于认为每一步都有相同真实贡献，只是粗粒度估计。

对第 i 条轨迹、第 t 次调用、第 k 个策略 token，保存真实条件 c，再计算：

\[
\rho_{i,t,k}=\exp\{\log\pi_\theta(y_{i,t,k}\mid c_{i,t,k})-\log\pi_{\mathrm{behav}}(y_{i,t,k}\mid c_{i,t,k})\}.
\]

将 ρ 与 A 放入 PPO/GRPO 的 clipped surrogate，对策略 token 聚合，得到可反向传播的损失。按轨迹、按调用、按 token 平均会产生不同权重，必须显式选择。

关键实现：

- 工具返回属于观测，不作为策略动作标签计入 policy loss；它仍作为后续决策的输入，影响学习。
- 保存并重建每次实际上下文。若执行时使用摘要，不能训练时换成完整历史，再声称计算了同一条件下的概率比。
- 采集时不必保存数小时计算图，更新时对保存样本重新前向。环境执行不需要可微。
- 区分终止、预算截断与基础设施故障。未完成任务怎样评分或过滤，是训练目标的一部分。
- 严格的组内结果优势在全成功或全失败时为零；其他正则项仍可能有梯度，但并没有提供哪条轨迹更好的结果信号。

更新可能使模型更经常定位相关文件、使用测试反馈、纠正错误和适时提交。是否真的学到这些行为，要看固定预算下的任务成功率与行为指标，不能从生成文字里的自我描述判断。

这些是对 [07 专题](07_长程Agent强化学习怎样实际训练.md) 的教学提炼，不是所有论文完全相同的实现。

## 5. 精选论文：从工程实例到近期方法

### 5.1 DeepSWE，2025-07：先看完整工作流程

类型：作者技术报告与开放项目。使用 R2E-Gym 的容器任务，模型执行搜索、编辑、命令与提交，以测试验收给终局反馈；修改后的 GRPO 处理多轮输出。重要改动包括环境观测 mask、leave-one-out baseline、裁剪与长度缩放、截断轨迹过滤。

它适合回答“现实仓库的操作怎样变成训练样本”。需要额外学习的主要是 rollout 和验收系统。它从已有 Qwen3-32B 继续训练，并非随机初始化语言模型；报告中的 pass@1 与使用多个候选/验证器的 test-time scaling 分数必须分开。

来源：[作者报告 §2–4](https://www.together.ai/blog/deepswe)。

### 5.2 Training Long-Context, Multi-Turn SWE Agents，2025-08：长度与环境工程

类型：论文。使用有仓库快照、问题描述和测试的 SWE-rebench 任务，筛选确定性与可执行性，采用基于 DAPO 的多轮训练方案。可结合 §2.2 与 §3 理解裁剪、无信号样本过滤、损失聚合和多阶段训练。它在本文实验中选择同步采样；不能因讨论了异步系统就把它说成异步训练案例。

来源：[原文](https://arxiv.org/html/2508.03501v1)。

### 5.3 Agent Lightning，2025-08：日志如何接入学习

类型：论文与框架。将完整执行分解为每次模型调用的 input/output/reward transition，再对接已有 token 级 RL。适合有摘要、动态模板、多个角色的工作流。

必须讲清的边界：原论文 §3.3.2 的实现把同一终局回报赋给每次调用；框架提供更复杂信用分配接口，不代表当时已精确识别每步贡献。

来源：[原文 §3.2–3.4](https://arxiv.org/html/2508.03680v1)。

### 5.4 G2PO，2026-06-22：把多条轨迹连成图

类型：近期预印本。在同任务的采样轨迹中，把相同观测合并成节点，行动作为边，聚合后续回报来估计节点价值。将轨迹级优势与节点局部比较、图上 TD 差值标准化结合，仍使用 GRPO 风格裁剪更新；实验包括 WebShop、ALFWorld 和 AppWorld。

讲述价值：整体失败的轨迹中也可能包含有价值的中间决策。实践推论：在部分可观测任务里，相同页面/工具文本不一定代表相同隐藏状态；合并依据和足够的跨轨迹重复访问是重要适用条件。不能把图结构估计说成无条件精确归因。

来源：[原文 §4](https://arxiv.org/html/2606.22995v1)。

### 5.5 FACTOR，2026-08-07：先分行动，再分 token

类型：近期预印本。用恢复中间状态后的短续跑校准价值估计，将终局信用分到各行动，再利用反馈条件下的似然差，在行动内部给 token 分配权重。配合行动内归一化与按行动平均，控制长度对更新权重的影响。

其信用守恒关系不等于每个 token 获得真实因果贡献。需要环境可恢复，也需要额外执行预算。适合在已经理解优势与损失归一化后再读。

来源：[原文 §3 与补充实验](https://arxiv.org/html/2608.07118v1)。

### 5.6 ProVer，2026-09-28：验证关键片段，再加信用

类型：新预印本。先从同任务的成功/失败尝试中，让 judge 提出成功轨迹里的可能关键片段；再恢复片段前后的完整环境及历史，各自用固定策略采样续跑。后续成功率之差提供片段价值增量估计；正值作为加项，加入选中片段策略 token 的 GRPO 优势。实验涉及 ALFWorld、WebShop、SearchQA。

要点：judge 决定在哪里验证，终局结果提供验证依据。它依赖状态恢复，并增加环境交互成本；正值截断有偏，不能声称整个更新是无偏策略梯度，也不能据此识别片段内部每个动作的因果效应。

来源：[原文 §3、附录 B](https://arxiv.org/html/2609.36178v1)。

## 6. 对一个关键片段做数值说明

以下数字仅用于教学，不是论文实测：

```text
片段前：从快照继续执行 8 次，2 次成功 → 估计价值 0.25
片段后：从快照继续执行 8 次，6 次成功 → 估计价值 0.75
差值：0.50
```

可以理解为：在当前策略和这些状态下，做完该片段后的成功前景更好。比单纯让 judge 评价“这步很聪明”更接近可执行验证。但 8 次抽样不确定性较大；恢复必须包括历史与外部状态；差值不证明该片段普遍有效，也不自动分辨片段内部哪一步最关键。

这与 AlphaZero 的联系在于利用额外模拟帮助决策评价；区别在于 ProVer 用选择性的边界续跑修正训练信用，不是把整个 Agent 系统改成棋类 MCTS。

## 7. 是否仍是 PPO 或 GRPO

许多方法保留概率比与裁剪的优化骨架。变化可以发生在五处：采集什么轨迹、怎样计算奖励、怎样估计优势、哪些 token/调用进入损失及怎样加权、何时更新与同步策略。不是每个新算法名都意味着全新网络结构。

也并非只能用 GRPO：调用级 Critic、Actor-Critic 和离策略方法仍是研究路径。原有 [ArCHer](https://proceedings.mlr.press/v235/zhou24t.html) 与 [07 的信用分配部分](07_长程Agent强化学习怎样实际训练.md) 可补充对照。不能据几个案例断言所有闭源 Agent 都使用同一个配方。

## 8. 放入报告与实战的建议

主线建议：DQN（价值学习）→ AlphaZero（搜索＋学习）→ 策略梯度/PPO → InstructGPT → DeepSeekMath/R1 → DeepSWE（完整交互 RL）→ ProVer（局部信用）→ 具身智能中的相似问题。这是讲述顺序，不是单线算法替代史。

90 分钟可分配：游戏与概念 12、梯度与 PPO 23、LLM 单轮 RL 20、多轮 Agent 15、具身智能 12、问答 8。Agent 部分只精讲 DeepSWE 和 ProVer，其余作备份。

实战建议仍从可重置的小型代码修复任务开始，先跑完整轨迹 GRPO，再比较局部信用。A3 节点是已知可用资源，但模型大小、并行度和框架适配要实测；NPU 内存不替代容器、CPU、磁盘与任务环境工程。成功率应在隔离测试任务和固定时间/token/工具预算下比较，区分 RL、SFT、推理搜索和工具改进的贡献。

### 听众可以追问的三个问题

1. 为什么工具返回的文字不计入策略动作 loss，却仍然影响模型更新？
2. 如果一条轨迹最终失败，是否意味着里面每个动作都应受惩罚？
3. 从关键状态多重试几次，得到的信号与直接训练 Critic 分别有什么成本与偏差？

所有近期工作的效果仅代表论文所报告的任务设置；本文补充了方法解释，没有增加本项目已完成训练的范围。
