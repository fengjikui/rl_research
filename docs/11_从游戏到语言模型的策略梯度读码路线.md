# 从游戏到语言模型的策略梯度读码路线

先把自己当作第一次接触强化学习的人。这次不要求记住整张算法年表：先看见一次决策怎样得到反馈，再看代码怎样改变下一次决策，最后理解语言模型与机器人为什么也能使用这套方法。

本次阅读有三个入口：游戏用[视觉策略梯度代码](../policy_lab/README.md)，语言模型用[手写 LLM PPO](../llm_ppo_lab/README.md)，机器狗用[宇树与 Isaac Lab 导读](../robotics_lab/README.md)。算法发展年份留在[策略梯度发展路径](../tutorials/lessons/D_策略梯度发展路径.md)，不必先读完它才能开始。

## 第一步 一辆赛车怎样与程序交互

想象你在屏幕前玩赛车：先看画面，再决定转弯或加速，游戏向前运行，告诉你刚才的操作带来了什么结果。强化学习代码也是这个循环。

- **观察 observation**：模型当前拿到的信息。这里是画面；为了看见运动变化，输入叠了最近四张灰度图。
- **动作 action**：真正交给游戏的操作编号，例如右转。
- **单步奖励 reward**：执行这一操作后，游戏立即给出的数字反馈。
- **轨迹 trajectory**：按时间排列的观察、动作、奖励等记录。

先读 [`envs.py`](../policy_lab/envs.py) 的 `GrayFrameStack.step()`。不用先理解卷积，只确认它把真实动作交给了现成游戏，返回下一幅观察、奖励、真正终止和时间截断两个标记。`reset()` 则是开新一局。

这一段要能说清：**模型负责选择动作，环境负责执行规则并返回反馈。** 我们没有为每个画面标注“标准答案应该向左”。

## 第二步 网络输出概率 与 DQN 的分数不同

现在看 [`policy_core.py`](../policy_lab/policy_core.py) 的 `VisualActorCritic.forward()`。卷积和全连接先把画面变成一组特征，再接两个输出头。

先只看 Actor：它输出动作 logits，再由 `Categorical` 转为概率分布。比如右转概率0.6、左转0.1，意思是训练时更容易采样到右转；这些数不是未来能拿多少游戏分。

DQN 则输出每个动作的预期回报估计 Q。神经网络都能通过反向传播训练，但“网络参数有梯度”并不是把 DQN 归为策略梯度的依据。策略梯度直接优化动作分布。

先暂时忽略 Critic 头。REINFORCE 只训练 Actor 所需的部分，后面再解释额外这个评价头有什么用。

## 第三步 概率如何变成真正动作

读 [`rollouts.py`](../policy_lab/rollouts.py) 中这几件事：

```python
logits, values = model(states)
distribution = Categorical(logits=logits)
actions = distribution.sample()
old_logp = distribution.log_prob(actions)
```

`sample()` 按概率抽动作；不是每次都取概率最大的按钮。`log_prob(actions)` 记录的，是这次**实际抽到的动作**有多大对数概率。它不是奖励，也不是从所有动作里重新选一个更好的动作。

先把 log 当成概率的另一种表示：概率0.5的自然对数约为−0.693，概率0.8约为−0.223。两者都是负数，但后者更大，对应的动作概率也更大。我们稍后提高的是这个已采样动作的 log 概率，负数本身不表示“动作不好”。

采样期间不需要保存一整局的神经网络计算图。我们先记下发生了什么，学习时重新把这些观察送入当前网络，才能计算有梯度的 log 概率。

## 第四步 奖励与回报为什么要分开

在一个简化的片段里，前两步没得分，第三步冲过一个有分数的区域。奖励依次是 `[0, 0, 1]`。若暂时不打折，从第一步开始的累计回报就是1，第二步也是1，第三步也是1。

回报不是只看最后一笔奖励；这里相同，是因为前两步刚好为零。若奖励是 `[1, -1, 3]`，从三个时刻开始的回报分别是 `[3, 2, 3]`。加入折扣后，较远的奖励还要乘相应折扣。

读 `monte_carlo_returns()`，它从后往前累加。它使用的是这条实际轨迹后面发生的奖励；这与 DQN 用“下一状态估值”组成自举标签，要分清楚。

## 第五步 先用 REINFORCE 看清一次参数更新

读 `score_function_loss()`，最关键的结构是：

```python
loss = -(log_probability * fixed_return).mean()
```

先把回报固定：回报为正时，最小化这个损失会推动已采样动作的 log 概率上升，回报为负时方向相反。“比预期更好”需要下一节的基准才说得清。环境本身不参与反向传播；可微的是网络算出的动作 log 概率。

这不是单次交互就能证明哪个动作最好。环境可能有随机性，后面还做过其他动作，网络又共享参数，所以需要很多轨迹形成统计上的更新信号。完整推导与一个参数的手算例子见[发展路径第三节](../tutorials/lessons/D_策略梯度发展路径.md)。

实际代码还处理折扣的外层权重和变长回合的平均：先对一局各动作的梯度贡献求和，再在各局之间取平均。第一遍先理解负号、log概率和固定回报这三件事，第二遍再核对归一化。

此时可以先运行轻量测试 `policy_lab/test_policy.py`，看一个动作在正、负反馈下的概率朝不同方向变化。真实赛车短测只是验证流程；它没有证明几秒钟就能学会赛车。

## 第六步 得分不错 但有没有比预期更好

如果有两个不同的游戏局面：一个本来容易得分，从这个局面继续正常能拿10分，这次拿8分；另一个很困难，正常只有2分，这次拿6分。单看正回报，两次都是正数；相对各自局面的预期，前者表现差，后者表现好。这里基准依赖局面，不是针对同一个局面的不同动作任意设置两套基准。

**baseline** 是用来比较的基准。**优势 advantage** 表示“这次结果比基准好多少”。Critic 学习估计从这个局面继续的大致回报，作为一种基准来源。

Actor 负责动作概率，Critic 负责价值估计。Critic 不是环境给的奖励，不是另一个裁判随意替任务打分，也不是像 DQN 目标网络一样只复制参数就可以。

第一次读代码时，只追踪这三条线：Actor 的动作 log 概率；停止梯度的优势；Critic 要拟合的固定价值标签。它们在哪儿相遇，梯度又流向哪儿，是这一段的重点。

## 第七步 GAE 和 PPO 分别在改什么

**先学 GAE，再学 PPO。** GAE 负责“怎样估计优势”，PPO 负责“拿着这份优势，怎样更新策略”。它们不是同一个概念。

GAE 先比较“这一步奖励加下一状态的价值”与“当前价值预期”，再把后续几个时刻的差异按权重合起来。先用一两步的数字核对，再读 `compute_gae()` 的倒序循环。真正终止没有这一局的后续价值；只是收集窗口结束，往往还需要估值。时间上限截断还必须避免接上下一局。

PPO 接着问：采一批轨迹很贵，能不能用这批数据多更新几次？可以，但当前策略渐渐偏离采样时的策略，必须保留原来的概率作为比较基准。

对同一观察和同一个已采样动作，计算“当前概率÷旧概率”，再与固定优势放进裁剪目标。旧概率在这批数据的多个更新轮次中保持不变。读 `ppo_clipped_loss()` 时，不要把它看成 Q 值回归，也不要把概率比裁剪与梯度范数裁剪混为一谈。

代码中的一个 rollout 批次可以触发多次 `optimizer.step()`。记录运行量时要分别看采集步数、rollout批数和实际参数更新次数，不能只看一个笼统的 updates。

## 第八步 把游戏按钮换成语言模型 token

LLM 的观察是“问题＋目前生成的前缀”，动作是下一个 token。生成回答就是一条轨迹。区别是评价器经常要等整份回答生成完，才知道是否正确。

先读[语言模型的奖励、回报与 PPO 逐步讲解](../llm_ppo_lab/逐步讲解_LLM的奖励回报与PPO.md)，再读代码。顺序是：先把回答分成token，标清哪些是模型动作；再放入最终分数；再加入参考模型的偏离惩罚；最后用价值估计计算优势与 PPO 损失。

这一部分专门区分四个量：任务最后得几分、每个token的训练奖励、从某token开始的回报、减去价值基准后的优势。它们可能相近，但不是四种同义词。

先用微型因果语言模型观察完整张量与日志，再去读真实 Qwen＋LoRA 的入口。微型例子只为了看清机制，不冒充预训练大模型能力提升；旧 Qwen GRPO 的真实结果仍单独保留在 [grpo_lab](../grpo_lab/README.md)。

## 第九步 再去看一只机器狗

机器狗的观察可以是关节与机身状态，动作则是连续数值，例如关节位置目标。它的奖励通常每个控制周期都有：是否跟上速度指令、是否站稳、动作是否平顺等。

底层 PPO 不必换成一种神秘的机器人专属优化器。更多不同在物理仿真、控制接口、奖励组成、并行采集和迁移配置。看懂[官方代码导读](../robotics_lab/README.md)里的一个控制周期，再看完整训练循环。

本仓库不声称已经训练过宇树或在 A3 上运行过该仿真。NVIDIA 部署说明使用核对过的官方代码版本；实体机器人部署属于后续工作。

## 怎样检验这一节是否真的理解

每次只回答一个问题，不急着把所有术语背完。最先能复述这句话就够了：

> 我们先按策略概率做动作，拿到环境反馈；再对实际做过的动作重新计算概率，用回报或优势加权，形成损失，反传更新策略。

往后每一节只在这条主线上增加一个需要解决的问题：降低波动、估计后续反馈、控制更新幅度，或换成更复杂的任务。
