# 本次代码与讲义评审记录

日期：2026-11-03。目标是让读者能按“具体任务 → 一次交互 → 训练信号 → 参数更新”的顺序学习，而不是先背完整算法年表。入口见[逐层读码路线](11_从游戏到语言模型的策略梯度读码路线.md)。

## 怎样评审

本次由主代理整合，安排多个 AI 子代理分别编写与独立评审。它们不是人类专家评审，不提供训练效果保证。

- 代码作者负责手写 LLM PPO 与小型测试；另一个代理独立检查公式、边界、概率对齐和恢复逻辑，主代理阅读实现并从原始 JSON 独立复算。
- 机器人文档作者核对固定版本的一手源码；另一代理交叉读取任务注册、奖励、PPO 与视频入口，主代理复核讲解和命令组织。
- 两位子代理分别从算法正确性与初学者视角阅读讲义，主代理按反馈修正概念的前置说明与例子。

## 实际发现并修正的问题

| 问题 | 为什么重要 | 已做的修正 |
|---|---|---|
| 游戏 PPO 把 rollout 批数称为参数更新次数 | 一批会触发多个 epoch/minibatch 的 optimizer.step，混称会误判训练成本 | 分别记录 rollout_updates 与 optimizer_steps；旧记录保留并添加有依据的派生解释 |
| 变长回合直接按 token 平均可能改变 REINFORCE 的目标权重 | 不能把随机总长度缩放当作严格的每回合平均 | 明确每回合求和再对回合平均，附不同长度回合的手算测试 |
| LLM LoRA 恢复只检查多余键，没有拒绝缺失参数 | 可能把残缺 adapter 悄悄加载成部分随机初始化状态 | 恢复前严格比较完整键集合与 tensor shape，添加缺失拒绝测试 |
| HF 生成与重算概率缺少左 padding 的直接核验 | 第一个回答 token 的位置偏移或 attention 错误会破坏 PPO 比值 | 用本地随机小 Qwen 逐 token 采样，与整串重算逐个有效 token 比对 |
| 检查点中的 torch 版本号不是普通字符串 | restricted weights_only 加载会拒绝该对象，导致不能续训 | 保存普通字符串，并加入真实 CLI 的保存、恢复、只推理集成检查 |
| baseline 例子可能被理解为同一局面按动作任意设基线 | 容易误读状态 baseline 的作用 | 改为两个不同游戏局面，明确基准依赖状态 |
| 初次遇到 log 概率和 λ 就直接给公式 | 新读者缺少直觉，难以理解负号和 GAE | 先用0.5、0.8的log概率和λ两端含义，再进入公式与手算 |
| 机器人连续动作混用概率与概率密度 | 连续动作向量的 PPO 比较的是密度比 | 统一说明概率密度，并补一轮5×4=20次参数更新 |
| 官方机器人 main 已改过入口 | 混用新旧文档会给出无法运行的路径 | 固定 Isaac Lab v2.3.2 与 RSL-RL 3.1.2，逐项核对任务ID和命令 |

## 代码验证

本机长训练保持停止，未在这轮交付中启动大模型、物理仿真或 GPU 长训练。新增验证采用保守 CPU 线程数与秒级预算。

| 检查 | 结果 | 范围 |
|---|---|---|
| DQN 回放与标签 | 2 项通过，CPU-only | 环覆盖、跨局帧、终止标签、目标停止梯度、实际参数变化 |
| Rainbow 核心 | 6 项通过 | C51投影、NoisyNet、PER、多步边界、Double选择、重要性加权与KL优先级 |
| 游戏策略梯度 | 10 项通过 | 正负优势、变长回合平均、GAE边界、旧概率固定、实际更新计数与旧检查点迁移 |
| LLM PPO | 11 项通过 | EOS/PAD、奖励一次、signed KL、GAE、因果对齐、HF小Qwen+LoRA、严格恢复、CLI续训与只推理 |
| 原始 LLM rollout 独立复算 | 通过 | 不调用训练函数，从 JSON 重算奖励、优势和 Critic 目标，最大误差小于1e-5 |
| 机器人文档交叉核验 | 通过静态核对 | 固定源码的任务ID、时间步、奖励dt、超时实现、train/play参数；没有启动仿真 |

早期真实 CarRacing CPU 短测保留在 [policy_lab 的说明](../policy_lab/README.md)；短测只证明流程。初次 PPO 的67批数据对应134次参数更新，原始验证快照没有被改成更好看的结果。

本次微型 LLM 的真实 rollout、推理和核验见[公开证据](../llm_ppo_lab/evidence/tiny_cpu/README.md)。它的任务奖励和成功率没有显著提升，不能用 loss、权重变化或测试通过来声称语言能力提高。先前 Qwen GRPO 的窄任务提升则另见[完整实测记录](../grpo_lab/RESULTS.md)。

## 还没有验证什么

没有在4090上测量本次预训练Qwen PPO的显存、速度与准确率提升；没有在A3上适配，也没有运行Go2仿真。Craftium插件接口尚未做实际部署。相关运行文档是明确的下一步入口，不是已经完成的实验结果。

公开仓库保留代码、讲义、固定数据划分和精选证据。大容量回放、长程逐更新日志、基础模型缓存和大多数本机优化器检查点不提交；不会因为打开仓库或文档自动恢复训练。
