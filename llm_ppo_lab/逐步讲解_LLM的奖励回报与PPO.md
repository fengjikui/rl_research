# 语言模型的奖励 回报与 PPO 逐步讲解

这篇先讲一份回答怎么变成训练数据，再看代码。你不必一开始就会 KL、GAE 或 PPO 的公式。先把它看成一个会按概率选择下一个词的小程序：写完回答，拿到评价，再调整下次怎么写。

配套代码在[本目录 README](README.md)。微型后端用来看到完整计算；HF 后端使用真实预训练 Qwen 与 LoRA。微型短测验证流程，不表示预训练大模型已经训练出能力提升。之前真实 Qwen 的 GRPO 训练与完整推理证据仍在 [grpo_lab](../grpo_lab/README.md)，不能混为本次 PPO 的结果。

## 一 从回答一个问题开始

用户问：“把12反过来，只输出答案。”模型写出“21”并结束。

为了看清过程，暂时假设数字各占一个 token，结束符也是一个 token；微型后端正是这种定义。真实 Qwen 的 token 切分需查看 tokenizer，不能假定一个字或一个数字永远是一个 token。

```text
问题                 → 选择第一个动作：2
问题＋2              → 选择第二个动作：1
问题＋21             → 选择第三个动作：EOS（结束回答）
```

问题和已生成前缀相当于游戏里的观察；下一个 token 相当于动作。回答包含多个动作，所以即使人类只看到“一份答案”，训练时也可以把它看作逐步决策。

PPO 的训练动作通常按模型分布采样，而评估可以用贪心。我们没有把标准答案直接喂回每个位置要求它模仿；本次 RL 先让模型自己写，再用答案评价器打分。

## 二 先把四个容易混的量分开

| 名称 | 它在问什么 | 例子 |
|---|---|---|
| 任务分数 task score | 整份回答有没有完成要求 | 精确匹配答案给1，否则0 |
| 单步训练奖励 reward | 这个 token 时刻放进学习算法的反馈 | 可以是偏离惩罚，末 token 再加任务分 |
| 回报 return | 从这个时刻往后，奖励累计是多少 | 本步奖励加后面各步的折扣奖励 |
| 优势 advantage | 这次结果比这个前缀的预期好多少 | 用回报或估计目标减去价值基准 |

这四个量不是四种叫法的同一件东西。尤其任务最后得1分，不代表每个 token 的单步奖励都应设为1。

## 三 如果只有最终打分 怎么放到各 token 上

先不用参考模型，也不用 Critic。评价器对整份“21”给1分。最简单的终局奖励放法是：

```text
动作          2       1       EOS
单步奖励      0       0        1
```

这里把分数加在 EOS 对应的最后一个有效动作上；其他实现也可能使用别的边界约定，需要与 mask 一起核对。

不打折时，从每个位置开始的回报都是1。**这是因为后面最终有那1分，不是每个位置都重复领了1分。** 如果把单步奖励都设成1，三步累计就变成3，任务目标已经变了，甚至可能鼓励把回答写长。

代码从 `collect()` 得到 `task_scores [B]`，再由 `build_rewards()` 构造 `rewards [B,T]`：B 是回答数量，T 是这批回答补齐后的最大生成长度。任务分只在每条回答最后一个有效 token 加一次。

## 四 为什么还会出现参考模型

只追逐一个评分器，模型可能学出评分器喜欢、但我们不想要的写法。常见 RLHF PPO 会保留一个参考策略，用它约束当前策略不要偏离初始行为太多。这是训练目标的一部分，不是“概率变了就一定不好”。[InstructGPT 方法与附录](https://arxiv.org/html/2203.02155v1)。

在这份教学实现里，先比较实际采样 token 的两个 log 概率：

\[
k_t=\log\pi_{old}(a_t\mid s_t)-\log\pi_{ref}(a_t\mid s_t).
\]

再构造：

\[
r_t=-\beta k_t+\mathbf 1[t=\text{最后有效动作}]R.
\]

R 是整份回答的任务分，β 控制偏离惩罚的强弱。这里 `old` 是生成本批回答的策略，`ref` 是本实验固定的初始策略。

别把单个样本的 k 当成已经求完期望的 KL 散度：**k 可以为负。** 在旧策略下，对允许的所有动作取期望，得到的 KL 才非负；有限批次的样本估计也可能为负。这里采用的是常见的 signed sampled log-ratio 奖励写法，而不是逐 token 必定非负的惩罚。[RLHF PPO 实现说明](https://huggingface.co/docs/trl/main/en/ppo_trainer)。

这段计算不需要对评分器反传，也不沿参考分支反传。本轮奖励会固定下来用于后续优势和价值目标。

## 五 把它算成一张小表

以下是手算示例，不是本次真实采样记录。设回答正确，R=1，β=0.1，三个 token 的 sampled log-ratio 为 `[0.2, -0.1, 0.3]`：

| 动作 | sampled log-ratio | 偏离奖励 −βk | 最终任务分 | 本步总奖励 |
|---|---:|---:|---:|---:|
| 2 | 0.2 | −0.02 | 0 | −0.02 |
| 1 | −0.1 | +0.01 | 0 | +0.01 |
| EOS | 0.3 | −0.03 | 1 | 0.97 |

取 γ=1，把后续奖励累加，得到三个时刻的蒙特卡洛回报：

```text
从“2”开始：  -0.02 + 0.01 + 0.97 = 0.96
从“1”开始：          0.01 + 0.97 = 0.98
从EOS开始：                 0.97 = 0.97
```

整份回答的任务分是1，但加入偏离项后的整条回报是0.96。报告时应把答案正确率、任务分和带正则的训练奖励分别记录，不能只挑一个数叫“模型分数”。

γ 是折扣因子。语言模型的有限回答任务常使用 γ=1，因为不必仅凭答案位置远近就削弱最后评分；这不是所有 LLM 强化学习的强制规定。

## 六 Critic 是给每个前缀估值

Actor 预测下一个 token 的分布。Critic 预测的是：**从这个前缀继续写，预期还能获得多少训练回报。** 它不是下一个词的概率，也不是负责判定答案正确的奖励模型。

例如在生成第一个 token 之前，Critic 预计0.4；生成第二个之前预计0.5；准备结束之前预计0.2。若直接用上一节的完整回报减去这些价值，就得到 `[0.56, 0.48, 0.77]` 这样的优势。

实际 PPO 常用 GAE，在实际奖励和价值 bootstrap 之间折中。对这一批冻结的旧价值：

先给 λ 一个直觉：λ=0只使用一步 TD 残差；在完整有限回答、边界正确时，λ=1等于完整回报减旧价值；中间的 λ 混合不同跨度的信息。再看下面公式，就可以把每项对应到一个具体时刻。

\[
\delta_t=r_t+\gamma V_{old}(s_{t+1})-V_{old}(s_t),\qquad
\hat A_t=\delta_t+\gamma\lambda\hat A_{t+1}.
\]

真正结束后下一状态价值设为0；padding也不能接进递推。`finite_episode_gae()` 正在做这件事。

这份代码的 `returns` 字段是：

\[
\hat V^{target}_t=\hat A^{GAE}_t+V_{old}(s_t).
\]

**它是训练 Critic 的 GAE/λ-return 目标，不一定等于刚才直接累加的蒙特卡洛回报。** 在完整有限回答、λ=1且边界正确时，两者才在这里一致。

仍用上面的奖励与旧价值，λ=0.95 时，δ 为 `[0.08, -0.29, 0.77]`，GAE 优势为 `[0.499425, 0.4415, 0.77]`，Critic 目标为 `[0.899425, 0.9415, 0.97]`。先核对末项，再从后往前算，就能对应代码的循环。

Critic 用当前前向算出的价值去拟合这个固定目标；Actor 则用固定优势加权当前动作 log 概率。共享骨干会同时收到两种训练信号。

## 七 旧策略和参考策略到底有什么不同

| 对象 | 用途 | 什么时候变 |
|---|---|---|
| 当前策略 `policy` | 当前要训练的模型，重新计算 token 概率 | 每次参数更新都会变 |
| 旧策略 `old` | 生成本批样本时的行为概率，PPO 比值的分母 | 本批内固定，下一批重新采样时更新 |
| 参考策略 `reference` | 定义偏离正则的基准 | 本实验全过程固定；其他配方可能按阶段调整 |
| Critic | 预测前缀价值，帮助算优势 | 随学习更新；采样时的旧价值在本批内固定 |
| 奖励来源 | 判断整份答案质量 | 本例是确定的精确匹配程序，不是额外训练的奖励模型 |

这是五个**角色**，不要求在显存里摆五份完整模型。本实验旧策略主要保存为 rollout 的 log-prob 和 value 张量，不保留一份长期驻留的旧网络。

HF 后端只更新新建的 LoRA 和价值头；基础权重冻结，初始 LoRA 不改变模型输出，因此临时禁用 adapter 可以得到固定参考策略。它不适用于“随便加载一份已训练 adapter、禁用后仍叫同一个参考模型”的情况。微型后端则直接保存一份冻结参考副本。

## 八 PPO 真正计算损失的地方

数据采完后，本轮的 token、mask、旧 log 概率、旧价值、奖励、优势和价值目标都固定。每轮优化重新前向，得到当前 log 概率与当前价值：

\[
\rho_t=\exp(\log\pi_{new,t}-\log\pi_{old,t}).
\]

Actor 的裁剪目标与游戏 PPO 一样，比较同一前缀下**同一已采样 token**的新旧概率。它不要求知道正确 token；好坏来自回报或优势。

Critic 拟合上一节的固定价值目标，代码还使用 value clipping。Actor 概率比裁剪、value clipping 和 `clip_grad_norm_` 是三个不同的运算。我们在注释和函数参数里分别命名，不用一句“做裁剪”混过去。

这里 KL 已进入奖励，所以不再额外往同一个 PPO loss 中重复加相同的 KL 惩罚。GRPO 常见配方把 KL 直接放在目标中，不能不加区分地照抄过来。

日志中的 `approx_old_new_kl` 则在看新策略离采样时的旧策略改了多远；它与“相对固定 reference 的偏离奖励”是两种比较。优势也可以在有效 token 上做标准化来调整策略梯度尺度，但 Critic 的价值目标不跟着标准化。

## 九 哪些 token 可以参加损失

一个批次可能是：

```text
回答一：2   1   EOS PAD PAD
mask：  1   1    1   0   0

回答二：7   EOS PAD PAD PAD
mask：  1    1   0   0   0
```

问题里的 prompt token 不属于本次生成动作，不进入 policy loss；第一个 EOS 是模型选择的结束动作，要进入损失；EOS 后为了对齐长度补的 PAD 不进入损失。即使 PAD 和 EOS 使用同一个编号，也不能简单按“等于这个编号就全排除”处理。

计算第一个回答 token 的概率，要使用 prompt 最后一个位置的输出。`token_statistics()` 中的切片从 `P-1` 开始，因为那个 hidden state 还没看见第一个回答 token。价值也必须对应采取动作**之前**的前缀；如果用看完答案后的 hidden state 估此前价值，就泄漏了未来信息。

当前实现对所有有效回答 token 求平均，长回答有更多 token，也有更大的总权重。按回答各自平均后再按回答平均，是另一种目标权重，不能声称它们总是等价。微批梯度累积也按有效 token 数加权，以保持与整批同一目标一致。

## 十 EOS 和长度上限不是一回事

EOS 是模型主动结束；`max_new_tokens` 是外部预算。这个教学实现把“首个 EOS 或达到最大生成长度”都定义成有限任务的终点，终点后的 bootstrap 为0，记录中明确区分结束原因。

这是我们选择的任务定义，不是说所有长任务遇到时间上限都应把未来价值清零。若只是暂停采集、下一段仍会继续同一任务，通常应考虑 bootstrap；若对截断答案直接判分或过滤，也会改变优化目标。

缺少 EOS 是否罚分由任务规则决定。代码默认不额外处罚，`--missing-eos-penalty` 可以显式设置；不能在不同模型评估时偷偷改这个规则。

## 十一 为什么采样设置也会影响正确性

如果采样时用了 temperature、top-k、top-p，而记录旧概率时却按原始 logits 重算，那么 PPO 分母就可能不是实际采样分布。

为先讲清核心，本实现使用 temperature=1、无 top-k/top-p 的完整分布。采样和学习阶段都关闭 dropout，但学习时仍可反向传播：`model.eval()` 并不等于 `torch.no_grad()`。真正冻结旧数据与参考分支，靠的是 no-grad/detach 和参数设置。

实际高吞吐 LLM 框架还要处理生成后端与训练后端的数值一致性、不同策略版本、超长回答与批量调度。这些留在基础循环读懂之后再看。

## 十二 GRPO 放在什么位置比较

先看已有 [GRPO 核心](../grpo_lab/core.py)：同题采多份回答，计算组内相对奖励，形成优势。它不需要额外学习的 Critic；但仍需要评价答案，仍需保存行为概率与有效 token mask。

本节 PPO 的优势来自价值估计与 GAE；GRPO 的常见结果奖励版本从同组回答分数比较而来。两者都用概率比裁剪，但优势来源、价值损失、KL 放在哪里、长度归一化可以不同。GRPO 不是“把 PPO 的 Critic 删除，其他所有行照抄就自然等价”。[DeepSeekMath 第4节](https://arxiv.org/html/2402.03300v3#S4)。

已有 GRPO 数字反转案例的无 reference KL 配方也明确标注在原报告里。它是一个实测教学简化，不能冒充所有论文的完整配方。

## 十三 对照代码的最短路线

1. `models.py`：先只看 `TinyTokenizer` 和 `TinyActorCritic.forward()`，确认输入 token、因果遮罩、词表 logits 与价值。
2. `train.py → generate()`：看实际采样 token 与 EOS mask；再看 `collect()` 保存哪些旧数据。
3. `core.py → build_rewards()`：对着本节三 token 数字例子，确认最后加分一次。
4. `finite_episode_gae()`：从最后一步往前算出优势与价值目标。
5. `ppo_loss()` 和 `train.py → update()`：追踪当前概率、固定旧概率、Actor 与 Critic 梯度。
6. 最后再读 HF＋LoRA 的包装，把微型模型换成真实预训练模型；核心训练关系不变。

实验的 `rollout.json` 保存真实采样数字，不必加载权重或相信一张汇总表才能检查。先核对一个回答，再核对整个批次，最后再看训练前后的验证指标。
