# Part 1 · 强化学习基础

**这一段先集中认识术语，再用三个口头例子练习对应。** 建议讲 10–12 分钟。打砖块讲奖励和回报，斗地主讲状态和观察，大模型答题讲动作到底是什么。最后读一遍轨迹，区分状态价值和动作价值。

## 1 · 一次强化学习交互里有什么？

「有人负责做决定，有东西负责响应他的决定。做决定的是智能体，负责响应的是环境。智能体看到当前是什么局面，选一个动作。环境推进到下一个局面，同时给出这一步的反馈。下一步再来一遍。」

**环境收到（sₜ, aₜ） → 返回（sₜ₊₁, rₜ₊₁）**

这里从 **t = 0** 开始数。**aₜ** 是在 **sₜ** 做的动作，**rₜ₊₁** 是这个动作之后拿到的那笔奖励。也有材料把同一笔奖励记成 **rₜ**，读公式时先对齐下标约定。

| 中文 | 英文 | 常用符号 | 直观上回答什么问题 |
|---|---|---|---|
| 智能体 | agent | — | 谁在做决定？ |
| 环境 | environment | — | 谁根据决定推进局面、给反馈？ |
| 状态 | state | sₜ | 此刻世界处于什么局面？在常见的马尔可夫设定中，给定状态和动作，就足以确定下一状态和奖励的概率分布。 |
| 观察 | observation | oₜ | 做决定的人实际看到了什么？完整状态里可能有他看不到的部分。 |
| 动作 | action | aₜ | 这一步实际上做了什么？ |
| 策略 | policy | π、`π_θ` | 遇到这种局面怎么选？随机策略会给候选动作分配概率，θ 是模型参数。 |
| 状态转移 | state transition | sₜ → sₜ₊₁ | 做了这个动作，局面怎样变化？规则可以是确定的，也可以带随机性。 |
| 奖励 | reward | rₜ₊₁ | **做完这一步**，环境给了多少分？这笔反馈可以是零。 |
| 回合、终止 | episode、termination | T 为结束时刻 | 一段交互从哪里开始，到哪里算结束？ |
| 轨迹 | trajectory | τ | 这一路实际看到了什么、做了什么、拿到了什么反馈？把它们按先后顺序记录下来。 |
| 回报 | return | Gₜ | **从这一步往后**，在这条轨迹上一共拿到多少奖励？ |
| 折扣因子 | discount factor | γ | 远处的奖励在回报里算多重？γ = 1 时直接相加，γ < 1 时越晚的奖励权重越小。 |
| 期望回报 | expected return | E[Gₜ]、J(θ) | 给定条件和策略，把可能拿到的回报按概率加权，平均表现如何？J(θ) 常用来写策略要优化的目标。 |

**两个符号值得当场读一遍。**

- `π_θ(a | s)` 读作「给定局面 s，参数是 θ 的策略选动作 a 的概率」。竖线右边是条件。比如左移、不动、右移分别是 20%、20%、60%，一次只抽一个。换了局面，三个概率可以变。
- **E[G]** 读作「回报的期望」。如果事先知道零分概率 40%、一分概率 60%，那么期望就是 **0.4 × 0 + 0.6 × 1 = 0.6**。实际玩十局再算平均，会得到一个样本平均，用来估计这个期望。

**讲者备查。** 折扣回报写作 **Gₜ = rₜ₊₁ + γ rₜ₊₂ + γ² rₜ₊₃ + …**。

## 2 · 用三个例子把术语对上

### 打砖块 · 奖励是一步的，回报要往后看

「模型看见球往右下掉，就让挡板往右挪了一步。这一步没消掉任何砖，奖励是零。挡板接到球，球弹回去撞中砖，后来才拿到一分。站在最早那次右移往后看，如果先不打折扣，这一步起的回报就是一分。」

口头带过即可。挡板的走法是动作，球的运动和计分由环境决定。把每次看见的局面、按了什么和得到几分串起来，就是这局的轨迹。

### 斗地主 · 完整状态和玩家观察有区别

「三个人手里的牌加上桌上的局面，属于环境的完整状态。轮到你时，你能看到自己的牌和已经打出的牌，但你不知道别人手里还剩什么。模型是按它看得到的信息决定出一手牌，或者在规则允许时过牌。」

同一份观察可能对应不同的对手手牌。打出同样一手牌后，对手怎样应对也可能不同。如果我们把本方赢设为 1 分、输设为 0 分，那就是一条教学用的终局奖励规则。训练目标是多打几局以后更常获胜。

### 大模型答题 · 一步通常是选一个 token

「给模型一道题。现在的局面是题目加已经写下的内容。模型下一步选一个 token，选完就把它接在后面。回答还没写完时可以先不给分。整份回答结束，判题程序看看结果对不对。完整回答就是这一轮生成留下的动作序列。」

这个例子里，给定当前前缀和所选 token，新前缀就确定了。同一份完整回答在固定规则下也有确定的分数。**产生不同轨迹的一个原因，是同一个前缀下模型也可能抽到不同的 token。**

### 同一组问题再对一遍

| 想找什么 | 打砖块 | 斗地主 | 大模型答题 |
|---|---|---|---|
| 完整状态 | 球的位置和速度、挡板、剩余砖块 | 各方手牌、公开牌桌和轮到谁 | 在这个单轮例子中，用题目和回答前缀描述当前局面 |
| 观察 | 挡板、球和砖块的画面，可以提供连续画面看出球的方向 | 自己的手牌、公开的出牌记录和轮到谁 | 题目和已经生成的 token |
| 动作 | 左移、右移或不动 | 出一手合法的牌，或在允许时过牌 | 生成一个 token |
| 状态转移 | 挡板移动，球继续飞行或反弹 | 手牌和牌桌更新，轮到下一方 | 把 token 接到前缀末尾 |
| 奖励 | 例如这一步撞砖得 1 分 | 例如本方赢下整局得 1 分 | 例如整段答完且答案正确得 1 分 |
| 一条完整轨迹 | 从开局到命中或漏球 | 从发牌到分出胜负 | 从收到题目到生成结束 |

互动时可让听众换一个任务，只问三句。「这一步是谁在选？它当时看到了什么？反馈什么时候来？」能答出这三个问题，就能把术语迁移到新例子。

## 3 · 读一条轨迹，再定义两个价值函数

### 一条轨迹怎么写？

```text
τ = (s₀, a₀, r₁, s₁, a₁, r₂, s₂, …, sₜ, aₜ, rₜ₊₁, sₜ₊₁, …, s_T)
```

从左往右读。**在开局状态 s₀ 做动作 a₀，环境给出奖励 r₁ 和下一状态 s₁。** 再用 s₁ 选 a₁，得到 r₂ 和 s₂，直到终止。最后一个动作是 a_{T−1}，它带来奖励 r_T 和终止状态 s_T。r₁ 和 s₁ 是执行 a₀ 后同时拿到的两个结果。教材有时交换这两个量的书写顺序，读清每笔奖励和哪个动作对应就行。

这里的 a₀ 是**第一个动作**，o₀ 是**第一次观察**。如果记录的是玩家实际知道的东西，轨迹可以写成 `(o₀, a₀, r₁, o₁, …)`。斗地主就是一个例子，记录能从自己看到的手牌和出牌过程开始。

### 什么是状态价值 V，什么是动作价值 Q？

两者都看**从当前这一步开始的预期回报**。先固定一套策略 π，然后问两种问题。

| 中文 | 英文和符号 | 怎么想 |
|---|---|---|
| 状态价值函数 | state-value function，`V^π(s)` | 从状态 s 开始，连第一步也交给策略 π 选。这样玩，平均能拿多少回报？ |
| 动作价值函数 | action-value function，`Q^π(s, a)` | 在状态 s 先指定动作 a，第二步才继续按策略 π 走。从现在起，平均能拿多少回报？ |

```text
V^π(s)    = E_π[Gₜ | sₜ = s]
Q^π(s, a) = E[Gₜ | sₜ = s，首步指定 a，其余按 π 走]
```

**口述例子。**「假设在某个打砖块局面里，先往右再继续按策略玩，平均拿 0.8 分。先往左再继续按策略玩，平均拿 0.2 分。这是两个 Q 值。如果这套策略只在左右之间选，各占一半，那这个局面的 V 就是 0.5 × 0.8 + 0.5 × 0.2，等于 0.5 分。」

在同一状态下，**V 是按策略选各动作的概率，对各动作的 Q 加权平均。** 这里的数字只用来演示这层关系。后面讲基线时，再回到「这个局面通常能拿多少回报」这个问题。

## 4 · 点一下算法方向，转到策略梯度

- **价值方法。** 先学各个动作有多值，再用估值辅助选择。DQN 用这个思路玩过 Atari 打砖块。[DQN 论文](https://arxiv.org/abs/1312.5602)
- **策略梯度。** 直接优化决定动作概率的策略。PPO 属于这条线，在 Atari 和模拟机器人上都有实验。[PPO 论文](https://arxiv.org/abs/1707.06347)
- **结合规划或搜索。** 利用环境规则或模型考虑后续会发生什么。AlphaGo 用策略和价值辅助搜索，曾以 4 比 1 战胜李世石。这些方法可以组合在同一个系统里。[DeepMind 的 AlphaGo 回顾](https://deepmind.google/research/alphago/)

**转场。**「我们已经知道训练想让平均回报变高。真实训练里，能动的是网络参数。现在手边就一条经历，知道当时选了什么，也知道后来得了多少分。怎么把这条经历变成一个能反向传播的损失，让模型在相似局面下更常做出有利的动作？这就进入策略梯度。」
