# 05｜为什么换一个网络结构可能有用？

## 实验 A：同一幅网格，MLP 与 CNN

```bash
python tutorials/code/02_dqn.py --encoder mlp --out tutorials/runs/compare_mlp
python tutorials/code/02_dqn.py --encoder cnn --out tutorials/runs/compare_cnn
```

MLP 将 `[2,6,5]` 展平为 60 个坐标，每个位置有不同输入权重。CNN 保留二维关系：

```text
[B,2,6,5]
→ Conv2d(2,8,kernel=3,padding=1) → ReLU
→ Conv2d(8,16,kernel=3,padding=1) → ReLU
→ Flatten [B,480] → Linear(480,64) → ReLU
→ Q head [B,3]
```

卷积核在位置间共享权重，为“相同局部模式出现在不同位置”提供归纳偏置；边界、padding、步长和后续层会影响严格等变性。本例最终展平，因此整个网络不是严格平移不变的。

不能简单说 CNN 必定更强：小网格的信息很少，MLP 也能学会。两者隐藏尺寸与参数量没有匹配，本次结果不是“只有卷积这一个变量”的严格比较。查 JSON 的 `parameters` 与 `runtime.seconds`，再设计相近参数量、相同环境步、多个 seed 的实验。

一个更能验证空间共享的后续实验是：把局部模式移到训练未见位置，并控制边界影响，而不是只在同一 5 列上重复采样。当前脚本没有实现这种分布外评估。

## 实验 B：当前画面完全相同，答案为何不同？

代码：[04_memory.py](../code/04_memory.py)。第一帧显示左／右线索，之后四帧为空，最后出现相同的“现在回答”标记。前面没有可供模型写入环境的动作，最终才选 0 或 1，选对得 1 分。

```bash
python tutorials/code/04_memory.py --encoder mlp --out tutorials/runs/my_memory_mlp
python tutorials/code/04_memory.py --encoder gru --out tutorials/runs/my_memory_gru
```

| 结构 | 实际使用的输入 | 计算 |
|---|---|---|
| 无记忆 MLP | 最后一帧 `[B,3]` | Linear → Tanh → 2 logits |
| GRU | 全部帧 `[B,6,3]` | 逐帧更新 32 维隐状态 → 最后隐状态 → 2 logits |

两者使用相同的 REINFORCE 损失、环境奖励、batch 和更新次数。GRU 在时间上共享参数；这里通过整个短序列反向传播，而不是每次状态更新后 detach。

这里的对照刻意研究**历史是否进入模型**，并非让两个网络接收完全相同信息的容量排名。线索均衡时，最后一帧与答案独立，任何只读最后一帧的模型最多达到期望 50%；增加 MLP 层数没有办法恢复被丢掉的信息。

把所有历史拼接给 MLP 也可以解决这道固定长度题，所以不能得出“MLP 不能做序列任务”。GRU 的价值在于用固定状态、共享更新规则处理历史；其记忆仍有限，也会遇到长距离训练困难。

## 你应当记录什么

除了训练长度上的成功率，代码还测两倍延迟。后者只是两个线索的延迟探针，远不是一般长程推理能力。检查模型是否依赖固定位置、延迟变长后是否忘记、是否需要更大的状态或不同表示。

## 如何把实验扩充成结构研究

1. 加入“全历史展平 MLP”作为信息量一致的控制。
2. 训练使用多种延迟，测试更长延迟，区分记住固定位置与可变长度记忆。
3. 比较 GRU 与因果 Transformer，报告参数量、运行成本和成功率。
4. 加干扰线索，规定只有最初或最近某种标记有效，观察状态压缩与检索的差异。

上述四项是练习，不是本次已执行实验。每项先写清要验证的结构假设，再写网络代码。

结构设计的完整讨论见 [专题](A_如何设计新的模型结构.md)。GRU 来源可读 [Cho 等人的 Encoder–Decoder 论文](https://arxiv.org/abs/1406.1078)。
