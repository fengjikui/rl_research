# 08｜从两次工具调用走向长程 Agent

## 先让模型学会“先查再答”

代码：[06_tool_agent.py](../code/06_tool_agent.py)。环境隐藏一个 0／1。模型开始只看到 START，可以检查工具、提交 0、提交 1。如果检查，环境返回隐藏值，再允许一次动作；最多两次调用。正确得 1，错误得 0，检查收取 0.05 成本。

```bash
python tutorials/code/06_tool_agent.py --out tutorials/runs/my_tool_agent
```

模型沿用第 06 课的因果 Transformer，词表改为 6 个 token。动作约束为 inspect／submit0／submit1，因此训练与采样都只在三个合法动作 logits 上重新归一化。这是明确的接口约束，不是自然语言工具 JSON 解析。

## 一条成功轨迹的模型输入

```text
调用 1 输入：[START]
调用 1 输出：INSPECT
工具返回：BIT_0
调用 2 输入：[START, INSPECT, BIT_0]
调用 2 输出：SUBMIT_0
终局奖励：1 - 0.05 = 0.95
```

输入不包含隐藏值，直到模型选择检查。对环境隐藏值的访问只发生在评分和实际工具结果中，第一步策略无法偷看。

为方便向量化，代码也计算了未执行第二次调用的候选张量，但 `action_mask` 对它们完全清零，不作为执行数据、不进入 loss。每条轨迹的损失按实际调用求和再对轨迹平均，没有按调用数除一次。

## GRPO 在哪里

对同一个隐藏环境初态运行一组候选轨迹，计算组内结果优势，广播到该轨迹的所有实际动作。两次调用分别计算当前／旧策略 log-prob 和 ratio，再用 clip 目标更新。

工具返回 `BIT_0` 是第二次调用的输入，不是要预测的动作标签；模型不对环境结果的概率做交叉熵。它仍通过上下文表示影响后续生成梯度。

学习成功时，输出 trace 应从开始直接猜一个固定答案，变成检查后按返回值提交。均衡隐藏值下盲猜最多期望 50%，检查策略可达到 100% 成功率但净奖励为 0.95。区分任务成功率与扣成本后的奖励。

## 本实验没有证明什么

这是两种隐藏状态、至多两次调用的合成实验，不是小时级任务、代码 Agent 或未知网页的泛化。它验证的是工具反馈与轨迹 loss 的连接。若先把机制压缩到能枚举的例子，后面处理复杂环境才容易定位问题。

## 迁移到真实代码修复时，具体换哪些部分

| 本课 | 代码修复版本 |
|---|---|
| START | Issue＋固定仓库 commit＋工具说明 |
| 隐藏 bit | 缺陷、依赖状态、隐藏验收条件 |
| INSPECT | 搜索、读取、执行可见测试 |
| SUBMIT | 提交补丁并结束任务 |
| 一个工具结果 token | 文件片段、测试日志、退出码 |
| 两次调用 | 可变次数的真实操作与纠错 |
| 精确匹配奖励 | 独立测试验收、功能与回归结果 |

参数更新主干可以先保持轨迹级 GRPO，新增的是重置环境、保存实际上下文、长序列 batching、动作 loss mask、终止规则与执行调度。若引入 Critic，替换的是优势估计模块，不是整个 Transformer 必须重造。

## 建议的三个扩展关卡

1. **四次查询的合成工具任务：** 查询多个隐藏量，最后组合提交；考察信用分配与成本。先保留程序化工具、可枚举结果。
2. **小仓库修复：** 固定几个任务族，搜索／读取／编辑／测试／提交五种工具，控制在数次到十余次调用。先验证环境和初始成功率。
3. **更长真实依赖链：** 增加跨文件依赖、失败恢复、检查点与上下文压缩，再研究调用级 Critic、续跑反馈、异步采样与策略陈旧。

这是后续实施路线，本仓库没有伪装成已完成这三个扩展。不要为了“长程”故意加等待时间；长墙钟时间、长 token 序列和长决策链是不同量。

基线全失败时，优先处理探索与任务课程，而不是认为换 PPO 为 GRPO 就能解决。更细信用分配也需要可用的价值或反馈来源。
