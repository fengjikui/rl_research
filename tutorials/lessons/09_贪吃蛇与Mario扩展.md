# 09｜从接球迁移到贪吃蛇、飞机游戏与 Mario

本课是扩展实验指南，当前没有提供这些游戏的完整适配器或训练结果。先把接球的环境接口与算法看懂，再替换一项环境因素，比同时引入模拟器、复杂视觉、稀疏奖励与新算法更便于诊断。

## 贪吃蛇：状态设计与奖励设计

初版建议固定小棋盘，动作定义为直行／左转／右转，避免把立即反向这种规则错误混入探索。观测至少包含蛇身、蛇头、食物与朝向；只给头部附近危险和食物方向会丢掉全局路径与身体信息。

二维通道可交给 CNN，展平通道可交给 MLP。若使用压缩特征，应将“表示变化”与“网络结构变化”分开比较。奖励可从吃到食物 +1、死亡 −1 开始；额外距离奖励可能鼓励局部贪心，评估仍看食物数、存活和循环率。

特别检查：移动进入即将离开的尾格是否允许；食物不能生成在身体上；棋盘填满的成功终止；无进展步数上限属于任务失败还是采样截断。规则与 done 语义必须先确定，再计算 bootstrap。

先比较随机策略、简单追食物启发式与训练模型，记录每回合长度、食物数、死亡原因。不能只看存活时间，因为原地循环可能获得好看的数字。

## 飞机游戏：视觉与时间

初版可使用程序化网格敌机与子弹，动作先限制为左右移动，固定发射逻辑。后续再加入开火、弹药、敌机类型与奖励。逐项加复杂度才能解释失败来自感知、控制还是探索。

一帧往往无法判断子弹速度与方向，可堆叠历史帧或加入循环状态。训练与评估保持相同动作重复规则，并记录真实模拟帧数；同样 10000 次“决策”在不同 frame-skip 设置下不是相同交互预算。

## Mario：如何读官方完整案例

可从 [PyTorch 官方 Mario 教程](https://docs.pytorch.org/tutorials/intermediate/mario_rl_tutorial.html) 看环境包装、跳帧、灰度缩放、历史帧和 Q 网络如何接起来。其示例把连续四张灰度图组成 `[4,84,84]`，让模型获得运动信息。

不要直接在本教程的环境中叠装模拟器依赖。先创建单独环境，核对当前安装包与 reset/step API，再跑随机动作和短回放。官方示例包含历史 Gym 兼容分支；这些细节应按实际安装版本处理，不能把旧脚本当成已验证的新环境配置。

接入本课 DQN 前需要修改：网络输入尺寸、动作映射、replay 存储类型、真实终止／截断区分、frame-skip 后奖励累加、评估关卡与随机种子。接球 CNN 最后的 `Linear(480,64)` 是固定尺寸，不能直接吃 84×84 图片。

## 接口适配清单

| 字段 | 必须明确的契约 |
|---|---|
| reset | 返回观测与必要 info；种子控制范围 |
| step | 观测、奖励、terminated、truncated、info |
| observation | 通道顺序、数值范围、历史帧、是否自动 reset |
| action | 离散编号对应的真实按键组合 |
| terminal observation | 自动 reset 时如何取得最后一帧 |
| evaluation | 关卡、动作预算、帧预算、候选数、随机性 |

这里没有统一规定 truncation 总要 bootstrap：若只是收集器边界通常需要；若时间限制就是任务失败规则，需按所定义的有限时域目标处理。不要把 API 字段名当成任务语义的替代品。

先争取在一个可重复的小关卡看到改善，再测试没见过的布局或关卡。报告新规则上的下降同样有教学价值。
