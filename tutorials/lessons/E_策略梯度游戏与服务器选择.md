# 策略梯度的游戏与服务器选择

目标是用有实际游戏画面、难度适中的现成环境学习 REINFORCE、Actor–Critic 和 PPO，再连接大语言模型与机器狗。任务优先考虑现代维护的接口和可展示的学习变化，训练优先使用服务器。选择依据于 2026 年 11 月 2 日核对的官方资料。

## 游戏选择

**主候选是 Craftium 的 3D 任务。** 它基于开源 Luanti 体素游戏引擎，具有类似 Minecraft 的画面，采用 Gymnasium/PettingZoo 接口，相关论文发表于 ICML 2025。环境自带任务，不需要重新写游戏规则。[项目与论文入口](https://craftium.readthedocs.io/en/latest/)。

| 任务 | 展示内容 | 在课程中的用途 |
|---|---|---|
| `Craftium/Room-v0` | 在随机起点与目标之间移动、转向，尽快找到目标 | 第一轮检查采样、策略概率、价值和 PPO 更新；使用新种子评估 |
| `Craftium/SpidersAttack-v0` | 持剑移动、转向、攻击蜘蛛，观察击杀和生存 | 主要游戏展示：比较训练前乱动和训练后有目的的行为 |
| `Craftium/ChopTree-v0` | 在森林里寻找并砍树 | 进一步连接视觉探索、稀疏奖励和长程任务 |

这些名称与动作、奖励定义见[官方环境目录](https://craftium.readthedocs.io/en/latest/environments/)。先训练较短且能清楚判分的任务；完整开放世界的探索与资源合成留作后续。不能因为任务画面更丰富，就预先保证普通 REINFORCE 很快学会；它的高方差本身就是需要观察的现象。

**备用验证环境是 Gymnasium 的 `CarRacing-v3`。** 从随机赛道图像控制赛车，离散模式有不动、左右转向、油门和刹车五个动作；连续模式则输出转向、油门和刹车。它适合连接离散策略与连续控制。它是持续维护的现成环境，但不是新提出的研究任务，因此主要作为便于先跑通的备用方案。[官方文档](https://gymnasium.farama.org/environments/box2d/car_racing/)。

超级玛丽仍可以做扩展，但不预设某个旧版模拟器包装库能与当前 Gymnasium、Python 和 NPU 环境直接兼容。我们优先把时间花在策略学习与展示，而不是先处理旧接口迁移。

## 导包简单与首次部署是两件事

Craftium 安装完成后，可以采用熟悉的调用方式：

```python
import gymnasium as gym
import craftium  # 注册 Craftium 自带环境

env = gym.make("Craftium/Room-v0")
observation, info = env.reset(seed=0)
observation, reward, terminated, truncated, info = env.step(action)
```

首次安装并非只有一条 `pip install`：官方流程要求递归克隆源码和子模块，安装游戏引擎系统依赖，再编译安装 Python 包。Linux 无桌面服务器还需验证离屏渲染、OpenGL/Mesa 或虚拟显示的路径。代码可以复用已有任务，底层依赖仍需先部署。[官方安装说明](https://craftium.readthedocs.io/en/latest/installation/)。

## 单张 4090 的实施路径

这类小型 CNN Actor–Critic 不需要大语言模型规模的设备内存，单张 4090 足以作为训练设备。训练效率还取决于 CPU 上游戏引擎的采样速度、图像传输和并行环境数，不能只按显卡算力推算达到某分数的时间。

建议使用 Linux，CPU 至少保留 8 个可用核心，优先 16 个以上，内存优先 32–64 GB，并提供可用的离屏渲染与磁盘空间。它们是部署建议，不是已经测过的最低配置。先从 4–8 个环境测试采样吞吐、内存和 GPU 利用率，再决定增加并行度。

第一阶段只做安装、真实环境采样、损失与梯度检查、保存与重新推理。通过后用固定实际时间比较 REINFORCE、AC 和 PPO，记录环境步数、优化次数和所有评估分数。半小时、一小时或更长预算都可设置；是否已明显改善由实际评估决定，不提前承诺训练到某分数。

后续若转到 Isaac Lab 等 NVIDIA 机器人仿真生态，4090 在软件栈上更顺路；仍需核验所选仿真版本的驱动、图形与内存要求，不把一项游戏实验跑通当作所有仿真都能运行。

## 昇腾 A3 暂缓

A3 位于公司内网，当前没有可调试的实际环境，因此暂不进行昇腾适配或部署。当前优先完成讲解、通用 PyTorch 代码和真实游戏短测，再在可访问的 4090 上开展训练；以后拿到 A3 环境时再核验。代码中的 NPU 入口仅是预留接口，不代表经过 A3 验证。

## 展示与验收

主要展示同一组评估设置下，训练前、中期、训练后的行为与分数，不只展示最好的一局。游戏种子分为训练与评估，记录原始奖励、成功率或任务指标、动作及结束原因，并保留首个评估回合的录像。视频达到长度上限要标明截断。

REINFORCE 先讲清“完整回报如何乘到动作 log 概率”；AC 再加入价值 baseline 与 bootstrap；PPO 最后加入旧策略概率、GAE 与裁剪。这样观众看到的是同一游戏里的训练方法变化，而不是每换一种算法就换一套任务。

学习路径见[策略梯度的发展路径](D_策略梯度发展路径.md)。实现与服务器接力材料放在仓库 `policy_lab/`，实际兼容性以对应验证记录为准。
